## Что это

Универсальное ядро доступа агента к Google Docs / Sheets / Drive и локальным папкам.
Дизайн — [DESIGN.md](DESIGN.md), 16 разделов и 15 решений D-1…D-15; он источник правды,
любое изменение архитектуры = правка дизайна в том же коммите.

Два равноправных контура: **читающий** (карта файла, профиль колонок, сканирование
корпуса) и **пишущий** (превью до записи, адресация по именам колонок, вопрос вместо
догадки, откат). Мозг подключаемый: MCP-клиент, локальная модель, любой провайдер.

## Открытые хвосты

- **Код плана стоит на ненадёжной ревизии.** `plan.ts` кладёт `revision` в подпись
  намеренно, а `assertSafeToUndo` в `undo.ts` версию Drive не использует и объясняет почему:
  она растёт от нашей же записи. Замер живого прогона 2026-09-03: сразу после откатa чтение
  вернуло `37`, через минуту без единой записи — `39`; код того же плана съехал дважды при
  идентичных ячейках. Значит человек, читающий код сразу после записи, может получить
  `plan_mismatch` на честном подтверждении. Нужно решение по D-16, а не патч.
- **`revisionAfter` в строке откатa всегда `null`** (`undo.ts:119`), тогда как путь записи
  её читает. Журнал обещает «ревизии до и после» — для откатa обещание не исполнено.
  Оракула нет намеренно: он был бы красным, починка трогает журнал и требует поставки.
- **`findReplace` живой записью не проверен.** `formatCells` прогнан с человеком
  2026-09-03; замена пишет по коду плана и откатывается только в тестах. Шаги 3–4 в
  `delivery/archive/2026-09-03-hotkey-parity-format/live-run.md`.
- **Вход раз в неделю.** Приложение в Cloud Console в статусе Testing → Google обрубает
  refresh-токен через 7 дней. Ядро предупреждает с шестого дня (`gc_targets` → warnings).
  Снимается публикацией приложения — владелец решил делать её **в самом конце**.
- **CLI пишет мимо журнала.** `src/cli/manual.ts` зовёт `upsertRow` без `journal` и
  `journalSource`: из `gc upsert --write` не работают ни аудит, ни `write.plan-once`. Код
  плана передавать научился (`--confirm=<код>`). Чинится с CLI-фасадом фазы 3.
- **`policy://rules` отдаёт только прозу** `rules.md`; машинные правила (26 штук) через
  ресурс не видны. Решить: отдавать `rules.json` вторым ресурсом или не рассчитывать.
- **Мутационные слабые места:** `map.ts` 57%, `values.ts` 61%, `find-replace-op.ts` 66%.
  Поднять порог до 70 — задача следующей фазы; сейчас порог падения 50.
- **Три копии старого движка** (`Gdocs-tabs editor` в SEO:Content, local-web-agent,
  Event Content System) переведены на новый OAuth-клиент, но без токенов. Вывод из
  эксплуатации — фаза 3. Файл клиента оттуда однажды спас доступ, см. выше.
- **Telegram-токен** из старого `config.json` не перевыпущен (фаза 0, за владельцем).
- Фазы дальше: **2.5b** структурные операции, 2.7 полный `gc_scan`, 3 CLI и итог дня,
  4 раннер и панель (React + Vite + TS + Tailwind, liquid glass из `local-web-agent`).

## Gotchas — то, что уже стоило времени

- **Гейты судят, а не украшают.** `delivery_check` дважды не пустил коммит: объявленные
  права без `.claude/settings.json`, решение без цены. Формат решений строгий: «выбрал X
  **вместо** Y — потому что Z», иначе гейт отклонит.
- **Живой прогон находит то, чего не видят юнит-тесты.** Прогон в другом клиенте дал
  шесть настоящих дефектов; смена аккаунта — ещё три. Оба раза причина одна: тесты
  вызывали обработчик напрямую, а дефект жил на шве.
- **`npm run build` без `rm -rf dist/policy`** вкладывал папку в папку, и собранный сервер
  отдавал 14 правил из 17 при «успешной» сборке. Оракул S10 в smoke это ловит.
- **«Ничего не изменилось» ядро обязано называть само.** `dryRun:false` на «значение уже
  такое» возвращал `ok` и не писал журнал — человек читал «готово» при пустом факте. Теперь
  статус `no_change`. Тот же класс: `nothing_to_undo` без причины, и модель дописала
  «журнал пуст», когда все четыре записи были просто откачены.
- **Обещание реестра исполняет механизм, а не память модели.** `gc_targets` отдавал «лист
  по умолчанию: Проекты», а `gc_read`/`gc_apply` без явного `sheet` уходили на первый лист
  книги («Инструкция»). Порядок старшинства: аргумент вызова → реестр → эвристика.
- **Тест может закреплять дефект.** Property-тест «upsert идемпотентен» требовал `ok` от
  записи, которая ничего не меняет, — то есть охранял ровно то поведение, что оказалось
  дефектом. Оракул проверять на «краснеет ли он без правки».
- **Версия файла Drive растёт и от собственной записи** (16 → 17 → 18 за цикл). Откат
  сверяет НАШИ ячейки, а не версию, иначе отказывал всегда. Хуже: она ещё и **отстаёт** —
  2026-09-03 чтение сразу после откатa вернуло прежнее значение, а через минуту без записей
  выросло на два. Всё, что стоит на равенстве версий, ложно по построению.
- **`prompt=consent` без `select_account`** — Google не показывает выбор аккаунта, и вход
  уходит не туда. Оба значения обязательны, на это есть тест.
- **Поиск по Drive не видит всего, что читается по ID.** Файл, расшаренный ссылкой и не
  открытый в Drive, отсутствует в `files.list` при любом запросе. `gc_search` всегда
  печатает `incompleteBecause`.
- **macOS даёт bash 3.2:** ни `mapfile`, ни ассоциативных массивов — `check_grep_gate_ts.sh`
  написан портируемо.
- **Живой прогон вторым агентом находит то, чего не видят тесты.** 2026-09-02 — шесть
  дефектов против 190 тестов; 2026-09-03 — блокер и три дефекта против 266. Правила и три
  роли: `delivery/LIVE-RUN.md`. Главное условие — у тестера свой процесс сервера: своё
  соединение агента может быть СТАРШЕ правки.
- **Новый файл на языке вне масок гейтов — ложь контура.** `scripts/probe_mcp.mjs` не
  видел ни один гейт (маска длины была `*.ts *.py`), CI на main покраснел на
  `contour_doctor`: DEAD 1. Маски задаются env в `.pre-commit-config.yaml`
  (`LINT_LENGTH_GLOBS`), доктор это и проверяет — добавил `*.mjs`.
- **Коммит проверять по `git log`, а не по числу строк «Passed»**: хуки печатают успех
  своих шагов, а сам коммит при этом может не пройти.
- Секреты только в `~/.gconnect/<account>/` с правами 600. В `.gitignore` есть маска
  `client_secret*.json` — файл клиента не должен оказаться в репозитории под любым именем.
