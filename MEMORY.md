## Что это

Универсальное ядро доступа агента к Google Docs / Sheets / Drive и локальным папкам.
Дизайн — [DESIGN.md](DESIGN.md), 16 разделов и 15 решений D-1…D-15; он источник правды,
любое изменение архитектуры = правка дизайна в том же коммите.

Два равноправных контура: **читающий** (карта файла, профиль колонок, сканирование
корпуса) и **пишущий** (превью до записи, адресация по именам колонок, вопрос вместо
догадки, откат). Мозг подключаемый: MCP-клиент, локальная модель, любой провайдер.

## Gotchas — то, что уже стоило времени

- **Два списка одного и того же расходятся молча.** Перечисление операций у MCP-инструмента
  было рукописной копией списка ядра, мои поздние правки в него не попали (текстовая замена
  не нашла якорь и промолчала), и протокол отдавал 9 операций из 21 — при том что правила
  уверяли агента, что все есть. 382 теста молчали: они звали ядро и типизированную
  разводку, а схему транспорта с ядром не сверял никто. Лечится не правкой списка, а тем,
  что список один: перечисление берётся из `OPERATION_NAMES`, плюс сквозная проверка через
  протокол в `probe_mcp.mjs`.
- **В процессе схему транспорта не наблюдают вовсе** — её применяет только MCP-сервер.
  Поэтому оракул «операция проходит схему» в тестах может быть зелёным, пока протокол её
  отклоняет. Сквозная проверка обязательна.
- **Оракул с правильным названием — самый дорогой класс дефекта.** `assertContiguous`
  «проверялся» тестом, который смотрел ноль подошедших строк; оракул сортировки был
  зелёным при бездействующей сортировке, потому что фикстура была уже отсортирована.
  Читать оракулы надо теми же глазами, что спеку.
- **Карта врёт про листы книги.** Чтение фильтруется по одному листу, и `otherSheets`
  строился из усечённого снимка: на книге из семи листов показывал «других нет». Проверки,
  опирающиеся на состав книги, обязаны спрашивать книгу (`sheetTitles` — дешёвый вызов без
  сетки), а снимок теперь помечается усечённым и карта об этом предупреждает.
- **Дорогой отказ — тоже дефект.** `deleteSheet` читал книгу целиком (~28 000 ячеек) ради
  снимка, который всё равно не влезал в бюджет: 11–15 секунд, а однажды таймаут, положивший
  сервер. Бюджет теперь проверяется дешёвой оценкой по карте ДО чтения.
- **`git checkout <файл>` уносит несохранённую работу.** Так я потерял готовый
  `deleteSheet` посреди разделения файла и переписывал его заново. Перед откатом файла —
  коммит или копия.

- **Гейты судят, а не украшают.** `delivery_check` дважды не пустил коммит: объявленные
  права без `.claude/settings.json`, решение без цены. Формат решений строгий: «выбрал X
  **вместо** Y — потому что Z», иначе гейт отклонит.
- **Живой прогон находит то, чего не видят юнит-тесты.** Прогон в другом клиенте дал
  шесть настоящих дефектов; смена аккаунта — ещё три. Оба раза причина одна: тесты
  вызывали обработчик напрямую, а дефект жил на шве.
- **`npm run build` без `rm -rf dist/policy`** вкладывал папку в папку, и собранный сервер
  отдавал 14 правил из 17 при «успешной» сборке. Оракул S10 в smoke это ловит.
- **«Ничего не изменилось» ядро обязано называть само.** `dryRun:false` на «значение уже
  такое» возвращал `ok` и не писал журнал — человек читал «готово» при пустом факте. Теперь
  статус `no_change`. Тот же класс: `nothing_to_undo` без причины, и модель дописала
  «журнал пуст», когда все четыре записи были просто откачены.
- **Обещание реестра исполняет механизм, а не память модели.** `gc_targets` отдавал «лист
  по умолчанию: Проекты», а `gc_read`/`gc_apply` без явного `sheet` уходили на первый лист
  книги («Инструкция»). Порядок старшинства: аргумент вызова → реестр → эвристика.
- **Тест может закреплять дефект.** Property-тест «upsert идемпотентен» требовал `ok` от
  записи, которая ничего не меняет, — то есть охранял ровно то поведение, что оказалось
  дефектом. Оракул проверять на «краснеет ли он без правки».
- **Версия файла Drive растёт и от собственной записи** (16 → 17 → 18 за цикл). Откат
  сверяет НАШИ ячейки, а не версию, иначе отказывал всегда. Хуже: она ещё и **отстаёт** —
  2026-09-03 чтение сразу после откатa вернуло прежнее значение, а через минуту без записей
  выросло на два. Всё, что стоит на равенстве версий, ложно по построению.
- **`prompt=consent` без `select_account`** — Google не показывает выбор аккаунта, и вход
  уходит не туда. Оба значения обязательны, на это есть тест.
- **Поиск по Drive не видит всего, что читается по ID.** Файл, расшаренный ссылкой и не
  открытый в Drive, отсутствует в `files.list` при любом запросе. `gc_search` всегда
  печатает `incompleteBecause`.
- **macOS даёт bash 3.2:** ни `mapfile`, ни ассоциативных массивов — `check_grep_gate_ts.sh`
  написан портируемо.
- **Живой прогон вторым агентом находит то, чего не видят тесты.** 2026-09-02 — шесть
  дефектов против 190 тестов; 2026-09-03 — блокер и три дефекта против 266. Правила и три
  роли: `delivery/LIVE-RUN.md`. Главное условие — у тестера свой процесс сервера: своё
  соединение агента может быть СТАРШЕ правки.
- **Новый файл на языке вне масок гейтов — ложь контура.** `scripts/probe_mcp.mjs` не
  видел ни один гейт (маска длины была `*.ts *.py`), CI на main покраснел на
  `contour_doctor`: DEAD 1. Маски задаются env в `.pre-commit-config.yaml`
  (`LINT_LENGTH_GLOBS`), доктор это и проверяет — добавил `*.mjs`.
- **Фейк, построенный по документации, согласен сам с собой (L23 — снова).** Живая сверка
  2026-10-01 нашла 4 расхождения фейка с Google, и каждое делало зелёными целые классы
  оракулов: у таблицы есть закрывающий юнит; insertTable режет абзац и ставит `\n` перед
  таблицей; новая строка/колонка копирует стиль ячейки-образца; удаление ЦЕЛОГО абзаца не
  трогает следующий. Плюс по документации: перенос перед таблицей удалить нельзя.
  «Оракул на числах», сверявший table-math с фейком, был кругом.
- **Шов собирается из частей, которые по отдельности верны.** `withRetry` переводил сырую
  ошибку в `bad_request` раньше, чем её читал распознаватель ревизии, — `doc_changed` был
  недостижим живьём при зелёном тесте на фейке, бросавшем готовый `doc_changed`.
  Разбирать ответ Google — ВНУТРИ повторяемой функции; клиент-шов тестировать на
  ЖИВОЙ форме ответа через внедрённый API (`GoogleDocsClient({api})`).
- **Объект занимает юниты без текста.** Картинка, @-чип, дата, разрыв — по 1 юниту; шов,
  бравший только textRun, сдвигал всё индексное после объекта. Разрыв страницы Google
  вставляет С переводом строки.
- **Вставка наследует ВСЁ у точки вставки** — стиль символа слева, вид абзаца, в который
  легла. Восстановление задаёт стиль точной маской (все поля в `fields`, лишнее
  сбрасывается) и вид абзаца без условий; две копии «вида абзаца» уже разошлись (L21).
- **Читатель без прогона снова дал больше всех:** 26 обещаний без механизма + 26
  оракулов, проверявших соседнее, — включая агенту в rules.md «правок в Docs нет, не
  предлагай» и повтор фразы, делавший замену дважды. Числа в прозе правил с кодом не
  сверял никто — теперь оракул сверяет ИМЕНА операций в разделах со списками ядра.
- **Живая сверка шва — своими скриптами на своих черновиках:** импорт `dist/...` по
  абсолютному пути (`pathToFileURL`), `googleapis` через `createRequire(package.json)`
  проекта, `ensureAccessToken` из `dist/core/auth.js`, документ — `documents.create`, в
  корзину в `finally`. Так проверяется код продукта, а не пересказ; вид документа
  сравнивать через `sectionBreak`-фильтр (первый элемент тела — разрыв раздела).
- **Коммит проверять по `git log`, а не по числу строк «Passed»**: хуки печатают успех
  своих шагов, а сам коммит при этом может не пройти.
- **`deps-audit` краснеет без единой нашей правки** — на новых advisories. 2026-10-01:
  high=2 (`fast-uri` через ajv MCP SDK, `brace-expansion` через googleapis → glob — оба
  РАНТАЙМ, не только dev) заблокировали любой коммит. Лечится `npm audit fix` отдельным
  коммитом (`95f7e55`, только патчи) → тесты → smoke → probe; `--no-verify` нельзя.
  Остаток — 2 moderate `qs` в `typed-rest-client`, точно пиненном stryker'ом: dev, не
  исполняется (нет dashboard-репортёра), закрывается только `overrides` — не делали.
  **Гейт печатает `js_total` ВДВОЕ больше `npm audit`**: однострочник канона суммирует и
  поле `total` (известно по `Prepare/field/reports/lab-5-real-c.md`, в CQG не исправлено).

- Секреты только в `~/.gconnect/<account>/` с правами 600. В `.gitignore` есть маска

- **Тест, зовущий обработчик, не видит транспорт — а дефект жил ровно там (LR3-5).** 574
