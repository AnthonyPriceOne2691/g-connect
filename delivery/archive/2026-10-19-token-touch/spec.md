# Spec: токен под пальцем — Google только через касание

Архитектура — [DESIGN.md](../../DESIGN.md) §11.5 (секреты вне проектов), §11.7 (scopes),
D-23 (разрешение проекта касанием); эта поставка вводит **D-24**. Открыта словом владельца
2026-10-17: «злонамеренную программу, запущенную под моим пользователем… как защитить
здесь? Опять же, пальцем» — и выбором «Да, следующей поставкой» с принятой ценой: соседние
сессии больше не берут токен напрямую, палец — на первое обращение сессии к Google и раз в
час.

Идентификаторы примеров — **U1…U14** («unlock»). X — прошлая поставка (cross-project),
T — задачи (§3.1d, урок L8).

## Problem

1. **Токен Google лежит открытым файлом.** `~/.gconnect/default/token.json` — refresh-токен
   (живёт до 7 дней, приложение в статусе Testing) и access-токен на час. Права 600
   защищают от других пользователей ОС, но не от программ под тем же пользователем: любая
   из них берёт refresh-токен и идёт в Google мимо G connect. Разрешение касанием (D-23)
   поэтому — граница согласия для агентов, а не изоляция.
2. **Access-токен тоже ложится на диск — каждый час:** `ensureAccessToken` пишет обновлённый
   токен обратно в `token.json`.
3. **Боковой дверью уже пользуются:** `portfolio-site/docs/sales/agencies/gsheet.py` читает
   refresh-токен из `~/.gconnect/default` и сам обновляет доступ; README «Mass email bomb»
   учит брать токен оттуда же. Это не теория — так работали соседние сессии.
4. **Удалить файл — не значит убрать токен.** Копии `token.json` живут в снимках APFS и в
   Time Machine. Убивает токен только отзыв в Google.

## Users / stakeholders

- Владелец: одна машина (MacBook Air M5, macOS 27, Touch ID), аккаунт Google `default`.
- Агенты в сессиях Claude Code (инструменты `mcp__g-connect__*`) и CLI `gc` в терминале.

## In scope

1. **Токен на диске — только шифротекст (D-24).** Refresh-токен зашифрован ключом Secure
   Enclave через `age` + `age-plugin-se` (Homebrew): `~/.gconnect/<account>/token.age`. Ключ
   — `any-biometry-or-passcode` (решение владельца): палец или пароль Mac.
   Рядом — `token.meta.json` без секретов (scopes, время входа) для статуса и `se-identity.txt`
   (ссылка на ключ анклава; без этого Mac она бесполезна). Шифрование требует только
   открытого ключа — без касания, поэтому вход и смена refresh-токена пишут сразу
   шифротекст: открытый токен на диск не попадает ни на миг.
2. **Открыть Google — касанием.** Расшифровка — только `age -d` с ключом анклава, macOS
   показывает Touch ID. Сервер расшифровывает refresh-токен, получает access-токен и тут же
   выбрасывает refresh-токен из памяти; access-токен живёт только в памяти процесса до
   истечения (~1 ч). Следующее обращение после — снова касание.
3. **Окно — только после строки агента.** Инструменты MCP сами окно не вызывают: при
   закрытом Google они отвечают `google_locked` с действием. Агент пишет человеку одну
   строку — «G connect попросит палец, чтобы открыть Google этой сессии на час» — и зовёт
   новый инструмент `gc_unlock`; окно вызывает только он. Так правило «окно не ждали — не
   касайся» становится выполнимым: окно G connect всегда объявлено в чате, вредоносное —
   нет. Команды CLI спрашивают палец сразу — команду набрал сам человек.
4. **Переход — один раз, командой владельца `gc seal`:** ключ анклава → пробная расшифровка
   (касание — человек в цепочке ДО необратимого) → отзыв старого входа в Google → новый вход
   в браузере, токен сразу шифротекстом → `token.json` удаляется. Отзыв — до нового входа:
   по документации Google отзыв снимает ВСЕ права приложения и гасит все его токены, не
   мгновенно; новый вход — только когда старый токен уже отвечает «отозван». Копии в
   снимках и бэкапах после этого — мусор.
5. **Видно, открыт ли Google.** `gc_targets` и `gc status` показывают «Google закрыт» или
   «открыт до HH:MM» и состояние профиля: зашифрован или открытый `token.json` (тогда
   предупреждение «запусти `gc seal`»). Статус касания не требует.
6. **Правила и памятка.** `policy://rules` и памятка в `~/.claude/CLAUDE.md` (скриптом
   `connect_claude.sh`, с резервной копией): с Google — только через инструменты G connect,
   токен самим не расшифровывать, перед `gc_unlock` — строка человеку, неожиданное окно —
   не касаться.
7. **Без инструментов `age` — отказ, а не открытый файл.** Нет `age` или плагина — `gc seal`,
   `gc login` и `gc_unlock` отказывают с действием «`brew install age age-plugin-se`»;
   откат к открытому токену не предусмотрен.
8. **Запасной ход `gc run -- <команда>` (решение владельца):** после касания команда
   получает access-токен на ≤1 ч в переменной `GOOGLE_ACCESS_TOKEN` — для того, чего
   G connect не умеет (письма, доступ по ссылке, комментарии). Refresh-токен не выдаётся
   никому. Пока команда работает, переменную видят программы того же пользователя — до часа.

## Out of scope (названо, а не забыто)

- **Активная программа под тем же пользователем.** Каталоги Homebrew, стабильная сборка,
  `node` и конфиги Claude Code пишутся этим пользователем: программа, подменившая `age` или
  сервер, дождётся ОЖИДАЕМОГО касания и получит токен. Это граница согласия, а не
  изоляция; изоляция — уровень платформы (отдельный пользователь macOS, подписанное
  приложение), не эта поставка.
- **Память работающего сервера** (отладчик под тем же пользователем) — до часа access-токена.
- **Ошибочное касание** неожиданного окна отдаёт refresh-токен тому, кто просил, до 7 дней.
- Сессия Google в браузере и программы, управляющие экраном или клавиатурой.
- Правка скриптов соседних проектов (`gsheet.py` в portfolio-site, README в «Mass email
  bomb») — их сессии; здесь только список того, что перестанет работать.
- Публикация приложения из Testing (вход раз в 7 дней) — решение владельца «в конце».
- Механизм разрешения D-23 (Secretive) и объединение двух касаний в одно: ключи разные,
  подпись ECDSA случайна — ключ шифрования из неё не вывести.
- Cursor и Codex.

## Acceptance (observable)

После `gc seal` открытого токена на диске нет, а старый вход отозван. Любое обращение к
Google из новой сессии проходит через одно касание после строки агента и дальше работает
до часа; без касания — ни одного запроса к Google. Скрипт, читающий `token.json`, перестаёт
работать.

## Non-functional

- Ожидание касания — не дольше 60 с, затем `unlock_declined`; остальные вызовы сервер не
  держит.
- `age` зовётся по абсолютному пути и с фиксированным `PATH` (каталог Homebrew и `/usr/bin:/bin`),
  а не с `PATH` сессии. Каталог Homebrew пишется тем же пользователем — это названо выше.
- Refresh-токен в памяти — только на время обмена; access-токен — до своего истечения.
- Ни токена, ни его фрагментов в журнале, аудите, ошибках и stderr.
- Тесты гоняют настоящий `age` с программным ключом X25519 (урок L32: фейк шва согласен сам
  с собой); анклав и окно Touch ID судит только живой прогон — это названо.

## Цена — то, что владелец принял 2026-10-17, числами

- Касание на первое обращение каждой сессии к Google и раз в час в долгой сессии: три
  параллельные сессии на восемь часов — до 24 касаний в день; плюс касание разрешения
  (D-23) раз в день на проект; каждая команда CLI, идущая в Google, — касание.
- Перестанут работать как есть: `gsheet.py` в portfolio-site, способ из README «Mass email
  bomb» и любые скрипты соседних сессий с токеном из `~/.gconnect`, включая письма через
  `gmail.send`. Их путь теперь — `gc run` (касание, токен на час) или инструменты G connect.
- В окне Touch ID — текст `age-plugin-se`, не наш: кто просит, видно только по строке в чате.
  В окне есть и поле пароля Mac: правило то же — окно не ждали, ничего не вводите.
