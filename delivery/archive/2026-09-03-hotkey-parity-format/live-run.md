## Пишущая половина: пройдена с человеком (2026-09-03, вечер)

Владелец произнёс код плана `b6206a` в Cursor; сервер пересобран из `dist` перед прогоном.
Формулировка: «сделай курсивом колонку Статус и её заголовок — только у проектов со
статусом „На приёмке“». Цель `infra-test`, лист `Проекты`.

- [x] превью по виду, а не по значениям: `F2` (шапка) и `F4` (G connect), `before == after`,
      `beforeFormat` шапки цел (`bold + align + background`), код плана шесть hex
- [x] строка `AutoLink Platform` («Разработка») под условие не подошла и не тронута
- [x] запись по коду человека: `status: ok`, ревизия 36 → 37
- [x] строка журнала `formatCells` со снимком вида «до», `planId`, `correlationId`
- [x] **`format` тела колонки подтверждён живьём** — дыра из «Непокрытого» закрыта: `F4`
      не была оформлена явно, курсив лёг, повторное превью ответило `no_change`
- [x] откат: `status: ok`, строка `undo` с `undoOf`, курсив снят с обеих ячеек, жирность,
      центрирование и фон шапки целы

Что нашлось и осталось (в оракулы не превращено намеренно, см. ниже):

- **`revisionAfter` в строке отката всегда `null`** — захардкожено в `undo.ts:119`, тогда
  как путь записи ревизию после себя читает (`readRevision`). Журнал обещает «ревизии до и
  после», и для откатa обещание не исполнено. Оракула нет: он был бы красным, а починка
  трогает журнал и требует своей поставки.
- **Код плана стоит на ревизии, которую сам же откат считает ненадёжной.** `plan.ts` кладёт
  `revision` в подпись намеренно («правка таблицы обязана менять код»), а `assertSafeToUndo`
  версию Drive не использует и объясняет почему: она растёт от нашей же записи. Замер этого
  прогона: сразу после откатa чтение вернуло `37` (запись уже прошла), через минуту без
  единой записи — `39`. Код того же плана съехал `b6206a` → `59cadb` → `52a2e8` при
  идентичных ячейках и видах. Следствие: человек, читающий код сразу после любой записи,
  может получить `plan_mismatch` на честном подтверждении. Это расхождение замысла D-16 с
  собственным выводом откатa — нужно решение, а не патч.
- Проверено и оказалось **уже названным**: откат ставит `italic: false` вместо «свойства
  нет». Это документировано в `undoFormat` (пустого формата в Google нет) и закрыто
  оракулом V4; чувствительность кода плана к ревизии — `plan.test.ts` «ревизия».

### Осталось из этого сценария: замена (шаги 3–4)

Курсив закрыл шаги 1–2 и 5–6 по виду; `findReplace` живой записью и откатом ещё не
проходил. Прогон в Cursor или в свежей сессии Claude Code, **перезапустив сервер**
(`dist` пересобран):

```
1. сделай шапку на листе Проекты жирной
2. пиши <код, который назвало превью>
3. замени в колонке Статус «На приёмке» на «Запущено»
4. пиши <новый код>
5. откати последнюю запись
6. откати последнюю запись
```

| # | Ждём | Дефект |
|---|---|---|
| 1 | превью: ячейки шапки, «было → станет» ПО ВИДУ, код плана; агент просит код у человека | план по значениям; агент подставил код сам |
| 2 | `status: ok`, в журнале строка `formatCells` с `planId` и снимком вида «до» | запись без строки журнала |
| 3 | превью списком затронутых ячеек | «заменено N» вместо списка |
| 4 | `status: ok`, в журнале строка `findReplace` | — |

| 6 | вид шапки вернулся | вид не вернулся |

Дополнительно, если не жалко минуты: на шаге 2 назвать **чужой** код (например `ffffff`) —
ждём `plan_mismatch`, отсутствие записи и НОВЫЙ план с новым кодом в том же ответе.
