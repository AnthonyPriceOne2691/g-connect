# Eval / smoke: вид, формулы, поиск (фаза 2.5a)

Галочка по факту, не по намерению. Каждый оракул проверен обратным прогоном (урок L7).

## Примеры спеки

- [ ] V1 — вид виден в карте (`bold` у шапки, `align` у числовой колонки)
- [ ] V2 — превью правки вида: ячейка, «было → станет», код плана, записи нет
- [ ] V3 — запись по коду: вид изменён, ЗНАЧЕНИЯ не тронуты, в журнале снимок вида «до»
- [ ] V4 — `gc_undo` вернул вид, значения по-прежнему целы
- [ ] V5 — частичная правка вида не сбрасывает остальные поля
- [ ] V6 — две правки вида в одном плане и одной строке журнала
- [ ] V7 — вид формульной колонки без `force` → `write_blocked`
- [ ] V8 — превью замены перечисляет ячейки, а не число
- [ ] V9 — значение с `=` попадает формулой; отдельной операции не нужно
- [ ] V10 — битое регулярное выражение → `bad_request`, ни одной правки
- [ ] V11 — неизвестное поле вида отклонено схемой до обращения к Google
- [ ] V12 — правка вида без изменений → `no_change` с причиной

## Что этот сьют НЕ проверяет (названо, а не замолчано)

- **Структурные операции** — 2.5b: вставка и удаление строк и столбцов, лист, копирование,
  автозаполнение, создание файлов.
- **Не «свой» вид ячейки.** Условное форматирование и тема дают видимый результат, которого
  нет в `userEnteredFormat`; ядро судит и откатывает только явный формат ячейки.
- **Числовые форматы, границы, объединение** — §6.2 их не требует.
