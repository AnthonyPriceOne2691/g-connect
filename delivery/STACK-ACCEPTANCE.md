## Остатки (не закрыто — и почему)

| Инвариант | Почему не закрыт | Компенсация |
|---|---|---|
| Каноны вне репозитория (вариант D) | репозиторий публичный: снимок в git раздал бы каноны; в CI файлов канона нет по построению | самопроверка канонов — в `Prepare/` при каждой их правке; скрининг состава и сверка тел — локальным доктором по `docs/canon/` и в CI по `scripts/lint/payload.lock.json`; `extract_payload.py --check-local`: отслеживается 0, без игнора 0 (2026-10-17) |
| Обход локального игнора | `git add -f` ставит в индекс и игнорируемый путь — закрыть на своей стороне нечем (§7.1a) | перед пушем ветки контура — `git ls-files docs/canon` пусто; правило записано здесь, а не в `.gitignore` (тот сам уехал бы в историю) |
| force-push / обход админом | серверной защиты ветки нет (CI и гейт мержа не развёрнуты) | правило в constitution «no force-push to main» + `deny: Bash(git push --force:*)` в правах агента |
| Серверная защита ветки | бесплатный тариф GitHub на приватных правилах; репозиторий публичный, но rulesets не включены | мерж только через `scripts/merge_guard.sh` + pre-push хук; `ci-oracles: tooling`, а не `deployed` |
| **Покрытие изменённого кода** | порога нет ни в `vitest.config.ts`, ни в CI: отчёт пишется, изменённый код по нему не судится | частично — мутационный гейт по изменённым файлам: мутант на непокрытой строке (`NoCoverage`) считается неубитым и роняет счёт доли; порог покрытия — решение владельца |
| Мутации вне диффа | гейт PR судит только изменённые файлы — неизменённый код ядра мутациями не перепроверяется | полный прогон ядра руками (`npx stryker run`, ~1 ч); последний — 2026-10-17, 63,84% при пороге 50 |
| python-половины гейтов (`pip-audit`, `mutmut`, `pytest-cov`, `ruff`) | прод-Python в проекте нет | половины честно пропускаются с названной причиной; TS-половины работают |

## Разбор: где эта процедура подвела

Записывать КАЖДЫЙ случай, когда приёмка показала зелено, а дыра была.
Формат: симптом → корневая причина → что добавлено в harness → как проверено.

- **2026-10-17, накат 2.55: снимок канонов чуть не уехал в публичный репозиторий.**
  Симптом: рецепт наката флота говорил «снимок `docs/canon` — стандарт, коммитьте».
  Причина: AGENT_STACK §7.1 различал «свой / чужой» репозиторий и молчал про «свой, но
  публичный». Добавлено: вариант D здесь — строки в `.git/info/exclude`, проверка
  `--check-local`; дыру в каноне чинит Prepare. Проверено: `git ls-files docs/canon` пусто
  в ветке наката и в `main`, `--check-local` — 0 и 0.
- **2026-10-17: роль «тесты утверждают» числилась незакрытой при работающем Stryker.**
  Симптом: `not-applicable.json` и эта таблица писали «Stryker не установлен», а CI
  гонял `npx stryker run` по всему ядру — 59 минут на PR #2. Причина: Stryker поставили
  мимо контура, записи не вернулись. С гейтом 2.55 устаревшее объявление стало бы
  выключателем: гейт читает его ДО работы и выходит «неприменим». Добавлено: объявление
  снято, гейт канона с поправкой (маска, доли, «не просудил» — красное). Проверено:
  `tests/mutation-scope.test.ts`, обратный прогон без маски — 2 красных; гейт на
  настоящем Stryker — 294 мутанта, 68%, 49 с.
- **2026-10-17, CI PR #4: доля мутаций красная при зелёном локальном прогоне.** Симптом:
  verify поставки cross-project — 70% по 14 файлам, OK; на CI доля 1/4 — 59% при пороге 60.
  Причина: доля судит свои файлы, а не сумму, а локальный прогон шёл без доли — алфавит
  сложил слабый `create-op.ts` (54%) с двумя крепкими. Добавлено: урок L31 — verify гоняет
  те же доли, что CI; оговорка в `ts_shard`; судить ли сумму последней джобой — решение
  владельца. Проверено: локальный прогон с `MUTATION_SHARD=1/4` воспроизвёл 163 из 273.
- **2026-10-17: «порог покрытия проверяется в CI» — порога не было.** Симптом: роль
  «покрытие изменённого кода» числилась адаптированной, шаг CI звался «Coverage
  (изменённый код)». Причина: `vitest --coverage` без `thresholds` — отчёт, а не гейт.
  Добавлено: роль названа незакрытой, шаг переименован. Проверено чтением
  `vitest.config.ts` и `package.json`: порога нет.
