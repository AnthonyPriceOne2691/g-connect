# Диагноз — длинные листы (D-26) и находки цепочки PR #9–#23

Журнал собран на verify из тестов-воспроизведений и обратных прогонов (`verify-report.md`,
раздел «Обратные прогоны»). Гипотезы, которые отбрасывались во время поиска в октябре, тогда не
записывались, — здесь только проверенное тестом. Это названная непокрытость журнала, а не
полнота поиска.

## Главный дефект: запись на листе длиннее 500 строк (Q1–Q7)

- **Чтение листа обрезано пределом `read.max-rows`** — ПОДТВЕРЖДЕНА: `getSpreadsheet` с названным
  листом читал `A1:ZZ500`; обратный прогон «запись снова по `A1:ZZ500`» → 3 красных (Q4, Q5, шов
  «лист целиком»).
- **Граница данных `appendRow` считается по обрезанному снимку** — ПОДТВЕРЖДЕНА: на листе в 600
  строк дозапись шла в `A501` — занятую строку (`tests/long-sheets.test.ts`, красный до починки).
- **`upsertRow` ищет ключ в том же снимке** — ПОДТВЕРЖДЕНА: ключ в 550-й строке не находился.
- **Предусловие `assertBeforeValues` видит строку 501 пустой** — ПОДТВЕРЖДЕНА: с пропуском в середине
  листа — отказ предусловия вместо дозаписи.
- **Граница по числу непустых строк вместо последней строки** — ОПРОВЕРГНУТА как починка: обратный
  прогон «`appendRow` по числу непустых строк» → Q4 с пропуском красный; граница — по последней
  строке со значением.
- **`truncated` у `gc_read values` по длине уже обрезанного ответа** — ПОДТВЕРЖДЕНА: обратный прогон
  «`truncated` по длине ответа» → Q2 красный (2 теста); признак берётся из размера листа.
- **Почему тесты молчали: фейк Google не моделировал обрезку** — ПОДТВЕРЖДЕНА: заглушка в
  `tests/long-sheets.test.ts` отвечает как Google (сетка только в запрошенном диапазоне, размер
  листа — в `gridProperties`, хвост пустых строк не отдаётся), и на ней воспроизведение красное.

## Находки следующих PR цепочки

- **Откат записи в пустую ячейку не возвращал пустоту (PR #10)** — ПОДТВЕРЖДЕНА: `null` в
  `values.update` Google пропускает ячейку, а не очищает; откат пишет `''`.
- **Создание по голому ID папки уходило в корень «Моего диска» (PR #12)** — ПОДТВЕРЖДЕНА: вид цели без
  типа теперь спрашивается у Drive, корень — только явным `root` (Q20–Q22).
- **Сортировка и снимки отката брали не всю ширину строки (PR #15)** — ПОДТВЕРЖДЕНА: колонки без
  подписи справа не ехали со строкой (Q33–Q35).
- **Пустой лист нечем подписать (PR #23)** — ПОДТВЕРЖДЕНА весть сессии профиля work: `upsertRow` по
  именам — «колонки нет», `appendRow` ключами `(A)…` — «подпиши шапку», операции подписи не было;
  сквозной тест `tests/set-header.test.ts` воспроизводит отказ до `setHeader`.
- **Режим карты «лист без шапки» (`headerRow: 0`) как починка (PR #23)** — ОПРОВЕРГНУТА как решение
  хотфикса: номер строки шапки стоит в 65 местах путей записи; выбрана явная операция `setHeader`.
