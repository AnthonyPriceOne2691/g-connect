# Plan: Google Docs — полное покрытие правки текста (уровень 3)

Класс L: новый шов с библиотекой (`documents.get` / `documents.batchUpdate`), новая модель
адресации (селекторы по тексту), новая форма снимка (текст со стилями), первый серверный
optimistic lock (`writeControl`). Слайсы идут от чтения к разрушению: каждая следующая
ступень опирается на проверенный механизм предыдущей.

## Slices

1. **Чтение: модель документа и карта.** Шов `documents.get` (с табами), доменная модель
   в ядре: сегменты, абзацы с UTF-16-границами, таблицы, стили. `gc_read` mode map | text
   для doc-целей. Фикстурный документ и фейк шва — ПО ДОКУМЕНТАЦИИ Google (семантика
   UTF-16, сдвиги индексов; урок L23). Примеры P21, основа P17. Чтение первым: адресация,
   превью и снимки стоят на нём, и карту сразу можно проверить глазами на живом документе.
2. **Селекторы.** `paragraphIndex`, `textStartsWith`, `textContains`, `afterHeading`,
   `firstParagraph`, `lastParagraph`, `tab`, таблица по номеру/якорю ячейки, escape hatch
   `startIndex/endIndex`. Совпало >1 — `needs_clarification` с кандидатами; 0 — ошибка с
   ближайшими. Пересчёт селекторов по документу, каким его оставила предыдущая операция
   вызова. Примеры P10, P15.
3. **План, журнал, предусловие.** Текстовое превью «было → станет» по абзацам; форма
   записи журнала: сегмент/таб, диапазон, снимок прогонов текста со стилями; ревизия в
   коде плана; `writeControl.requiredRevisionId` → `doc_changed`. Примеры P16, форма P1.
4. **Вставки и их откат.** `appendText`, `insertText`, `insertPageBreak`, `insertTable`,
   `insertTableRow`, `insertTableColumn`, `insertInlineImage` (URL; отказ на локальный
   путь ДО Google). Откат — удаление вставленного; охранник «вставленное не правлено»
   (сверка текста/objectId). Примеры P1–P4, P13, P17, P19, P19b.
5. **Подтверждение названием и конверт документов.** `NAMED_CONFIRM_OPS` для doc-операций,
   мера `maxChars`, отказ разбора конверта на разрушающей операции, отказ doc-операции на
   цели-таблице. Примеры P6b, P20, P22.
6. **Удаления и замены со снимком.** `deleteParagraph`, `deleteRange`, `deleteTable`,
   `deleteTableRow`, `deleteTableColumn`, `replaceText`, `replaceAllText` (снимок позиций
   ДО правки, откат по снимку); бюджет `write.snapshot-max-chars = 20000`. Примеры P5–P9,
   P14, P18.
7. **Стили.** `updateTextStyle`, `setParagraphStyle`, `createParagraphBullets`,
   `deleteParagraphBullets`; откат возвращает прежние поля из снимка. Примеры P11, P12.
8. **Правила, дизайн, живая проба.** Правила policy для документов (какие операции
   существуют, что в конверт, что требует названия); раздел Docs в DESIGN.md теми же
   коммитами, что код (урок L4); `probe_mcp` расширяется doc-пробой (схема собранного
   сервера против ядра — doc-операции, живое превью без записи); чек-лист живого прогона
   пар «правка → откат» на рабочем документе.

Слайс 7 (стили) — первый кандидат на вынос отдельной поставкой, если объём поедет: он
ничего не блокирует. Решение будет видно в tasks.md, а не случится молча.

## Rejected alternatives

- **Сквозной проброс `documents.batchUpdate`** (как у официального MCP Google: read +
  update) — отклонён, потому что такую правку нельзя показать
  «было → станет», положить в журнал и откатить. Каждая операция пишется руками, список
  конечен — зато «всё записанное откатывается» остаётся правдой.
- **Пара индексов как публичная адресация** — отклонена, потому что индексы сдвигаются каждой
  правкой, и «удали 120–180» между планом и записью становится чужим текстом. Селекторы
  §4 + ревизия в коде плана; голая пара остаётся escape hatch с тем же предусловием.
- **Предусловие перечиткой, как в Sheets** — отклонено, потому что у Docs есть родной
  `writeControl.requiredRevisionId`, серверный отказ. Своя перечитка рядом с ним — два
  механизма одного свойства, которые разойдутся молча (класс L14/L21: два представления
  одного и того же). Родному механизму — живой оракул в probe, фейку — семантика отказа
  по документации.
- **Откат `replaceAllText` обратной заменой** — отклонён, потому что обратная замена трогает и те
  вхождения строки-замены, что были в тексте ДО правки (P7). Снимок позиций до правки
  дороже одним чтением, но откат честный.
- **Один модуль операций на Sheets и Docs** — отклонён, потому что формы снимка и адресации разные,
  общий модуль склеил бы их в журнале и в плане. Общее — контур (план, конверт,
  подтверждение, журнал, undo), и он уже общий; доменные операции живут раздельно:
  `src/core/sheets/` и `src/core/docs/`.

## Риск и порядок

Самое опасное — слайс 6: там впервые уничтожается текст, и защита — снимок, который мы
сами построили, плюс подтверждение названием, которое к тому моменту уже работает (слайс
5), плюс предусловие ревизией (слайс 3). Самый широкий радиус у `replaceAllText` — она
одна правит десятки мест за раз, поэтому подтверждение названием всегда (решение
владельца) и снимок позиций, а не обратная замена. Аналога `moveDimension` (пустой ответ
Google, формула из документации) в Docs нет — арифметика отката здесь проще уровня 2, вся
она в сдвигах UTF-16-диапазонов, и на неё оракулы на числах из документации. Живая проба
удаления — только на абзаце, который владелец согласился потерять, и сразу с откатом.

## Уроки архива по затронутым путям (§2.2a)

Строка на урок: как применён — или почему не применим. Id — из `archive/INDEX.md`.

- **L2** (`src/`) — ветка `feat/docs-coverage`, мерж только `merge_guard.sh`, сразу за ним
  `contour_doctor`.
- **L3** (`src/core/google/`) — прямо применим: шов `documents.*` новый целиком, каждый
  запрос и каждый ответ фейка собираются по документации, и на числа из неё — оракулы
  (UTF-16, сдвиги, `writeControl`); живой прогон закрывает то, чего в документации нет.
- **L4** (`DESIGN.md`) — раздел Docs пишется теми же коммитами, что код слайсов;
  расхождение дизайна с реализацией ищется на верификации отдельным блоком.
- **L5** (`src/core/undo*`) — откат, вернувший не всё, называет недостающее сам: перенос
  правила `write.undo-names-what-it-cannot` на текстовые формы (стили, объекты).
- **L6** (`src/mcp/`) — каждое обещание в тексте ответа получает механизм: «карта
  предупреждает про suggestions», «отказ советует upload-поставку» — всё судится тестами.
- **L7, L22** (`tests/`) — каждый новый оракул гоняется обратным прогоном И читается
  глазами спеки: зелёный оракул на бездействующем откате уже случался; роль «читатель без
  прогона» входит в верификацию до живого прогона.
- **L8** (`delivery/`) — id примеров P-серия: T занята задачами, G/V/R/K — поставками;
  P-примеры не совпадают с нотацией доменных адресов Docs (там пары индексов, не буквы).
- **L9** (`stryker.config.json`) — область мутаций маской уже покрывает `src/core/**`;
  новые `src/core/docs/*` входят без правки конфига, проверить счёт после слайса 6.
- **L11** (`src/core/`) — порядок ветвей: бюджет снимка и вид цели проверяются ДО
  подтверждения и ДО записи; закрепляется оракулом на порядок (P18 до confirm).
- **L13** (`delivery/`) — примеры written от задачи владельца (контентные документы,
  комбайн ТЗ), спека до кода; честный счёт уровня 2 помнит: дыры в семантике Google
  примеры не ловят — на них живой прогон и фейк по документации.
- **L14** (`src/core/plan.ts`) — поля, которые кладёт одна сторона и читает другая
  (снимок ↔ откат, `confirmPhrase` ↔ охранник, ревизия ↔ writeControl), получают оракулы
  на СВЯЗЬ, не только на каждую сторону.
- **L16** (`src/core/`) — границы данных: «последний абзац раздела» ищется по границе
  раздела (следующий заголовок), а не по счётчику непустых абзацев.
- **L17** (`src/core/envelope.ts`) — строгость мерится применением: конверт разрешает
  ежедневные правки с первой фразы, подтверждение названием — только разрушающим.
- **L18** (`src/core/plan.ts`) — прокси в подписи запрещён: код плана держится на
  `revisionId` из Docs API, который сверяет СЕРВЕР (`writeControl`), а не на `version`
  Drive, который не сверяет никто.
- **L19** (`delivery/LIVE-RUN.md`) — чек-лист живого прогона: проверка повтора не ставится
  после отката; порядок пар выверяется на письме чек-листа.
- **L20** (`scripts/lint/`) — отказ гейта сложности/длины/дублей читается как сигнал о
  структуре: перевод селекторов и обратных операций — таблицами, не цепочками ветвей.
- **L21** (`src/mcp/apply-schema.ts`) — doc-операции входят в `OPERATION_NAMES`
  (единственный источник), транспортная схема берётся из ядра; сквозной оракул probe
  сверяет схему СОБРАННОГО сервера с ядром — он единственный, кто видит транспорт.
- **L23** (`tests/fixtures/`) — семантика фейка Docs не предполагается: `null`-уроки
  Sheets переносятся классом — каждый спорный контракт (пустой текст, границы диапазона,
  переносы строк `\n` как границы абзацев) фиксируется по документации и сверяется живым
  прогоном; фикстуры отката — абзацы РАЗНОЙ полноты стилей.
- **L24** (`scripts/probe_mcp.mjs`) — живые пробы не зависят от содержимого документа:
  превью на значении, уникальном прогону; отказы судятся операцией вне конверта.
- **L25** (`delivery/`) — о гейте отчитываться только прогоном с `--diff-base main`.
- **L1** — не применим прямо (не бутстрап); его симметрия — читатель без прогона на
  верификации (см. L22).
- **L10** — применим наполовину: контур подтверждения не меняется, но `gc_read`/`gc_apply`
  учатся различать вид цели — старые оракулы на sheet-путях обязаны остаться зелёными без
  правок; покраснели — значит, вид цели протёк не там.
- **L12** (`vitest.config.ts`) — три слоя изоляции тестовой записи не трогаются; новые
  сьюты пишут только в фикстуры; область мутаций не расширяется на `src/mcp/**` в этой
  поставке.
- **L15** (`delivery/LIVE-RUN.md`) — живой прогон контура подтверждения агентом проверяет
  механику, не подпись; оговорка пишется в чек-лист заранее, решение о делегации — слово
  владельца, не выбор агента.
