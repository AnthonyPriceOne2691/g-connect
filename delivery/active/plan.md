# Plan: токен под пальцем — Google только через касание

Класс L: новое решение безопасности (D-24 — токен Google шифруется ключом Secure Enclave),
восьмой инструмент (`gc_unlock`), смена хранения секретов и пути получения токена во всём
ядре, миграция с отзывом входа в Google. Слайсы идут от изолированного к связующему: шов
`age` и хранилище проверяются отдельно, прежде чем через них пойдёт каждый запрос к Google.

## Slices

1. **Шов `age`** (`src/core/token/age.ts`). Зашифровать — `age --encrypt --recipient
   <age1se1…> --armor`, открытый текст через stdin: касания не нужно. Расшифровать —
   `age --decrypt --identity <se-identity.txt>`, шифротекст через stdin, открытый — из
   stdout; окно Touch ID показывает плагин. Программы — по абсолютному пути (каталог
   Homebrew), `PATH` ребёнка фиксирован: каталог Homebrew и `/usr/bin:/bin` (плагин `age`
   ищет по `PATH`). Ожидание — 60 с, затем процесс убивается: `unlock_declined`. Ответ
   разбирается на три исхода: нет программы или плагина — `seal_tool_missing`; отмена или
   тишина — `unlock_declined`; прочее — `internal` с текстом stderr (секретов в нём нет).
   Ключ создаётся `age-plugin-se keygen --access-control=any-biometry-or-passcode`
   (решение владельца). Примеры U6, U8, U10.
2. **Хранилище профиля** (`src/core/profiles.ts`). `token.age` (шифротекст refresh-токена),
   `token.meta.json` (scopes, время входа, получатель — без секретов), `se-identity.txt`
   (600, каталог 700). Писатель принимает только шифровальщика: записать открытый токен
   нечем по построению. `profileStatus` читает метаданные, а не токен; открытый
   `token.json` — состояние `unsealed` с действием «`gc seal`», и токен из него ядро не
   берёт. Примеры U1, U9, U12.
3. **Хранилище токена процесса** (`src/core/token/vault.ts`). Одно на процесс сервера или
   команды. `accessToken()` — действующий access-токен из памяти либо `google_locked`;
   `unlock()` — расшифровка (касание), обмен у Google, refresh-токен выбрасывается тут же,
   в памяти остаётся access-токен до истечения (запас 60 с, как сейчас). Новый
   refresh-токен от Google — перешифровывается без касания. Одновременные `unlock()` —
   одно окно, а не два. Примеры U3–U5, U11.
4. **MCP** (`src/mcp/unlock-tool.ts`, `server.ts`, `tools.ts`). Восьмой инструмент
   `gc_unlock`: только он вызывает окно (правило `google.unlock-only-tool`). Инструменты,
   которым нужен Google, при закрытом отвечают `google_locked` с действием «скажи человеку
   строку и вызови `gc_unlock`»; `gc_targets` показывает «Google закрыт / открыт до HH:MM»
   без касания. Каталог ошибок: `google_locked`, `unlock_declined`, `seal_tool_missing`,
   `token_unsealed`. Правила — два новых машинных с пробами, текст `rules.md`. Проба
   считает восемь инструментов. Примеры U3, U12, U13.
5. **CLI** (`src/cli/manual.ts`). `gc login` — токен сразу шифротекстом. `gc status` — без
   касания, по метаданным. `gc seal` — переход: программы есть → ключ анклава → пробное
   касание (человек в цепочке ДО необратимого) → отзыв старого refresh-токена →
   ожидание, пока Google не ответит на него `invalid_grant` → новый вход в браузере, токен
   шифротекстом → удаление `token.json`. `gc run -- <команда>` — касание, ребёнку
   `GOOGLE_ACCESS_TOKEN` на ≤1 ч, код возврата ребёнка — наружу. Каждая команда, идущая в
   Google, спрашивает палец сама (её набрал человек). Примеры U1, U2, U9, U14.
6. **Тексты и подключения.** DESIGN: D-24, §11.5 (секреты), §3 (`gc_unlock`), §12;
   памятка агентам (`scripts/connect_claude_edit.py`: с Google — только инструменты G
   connect, токен самим не расшифровывать, строка перед `gc_unlock`, неожиданное окно — не
   касаться); исправить шапку `scripts/install_stable.sh` (про `.mcp.json` — опровергнуто
   замером X12, урок L33); CI ставит `age` для тестов шва (`quality.yml` — объявленная
   адаптация, запись в `adapted.json`); выжившие мутанты `secretive.ts` — тесты.
7. **Живой прогон** (шаги владельца — `live-run.md`): `brew install age age-plugin-se`,
   `gc seal` в терминале (касание и браузер), новая сессия в соседнем проекте — U3–U7,
   `gc run` на пробном скрипте, переустановка стабильной сборки и памятки. Пишем только в
   свой тестовый файл (урок L24).

## Rejected alternatives

- **Связка ключей macOS с доступом по биометрии** — отклонена, потому что такой элемент создаёт
  только подписанное приложение с entitlements, а `security` в терминале биометрию не ставит.
- **Ключ шифрования из подписи Secretive** — отклонён, потому что подпись ECDSA случайна: одна и
  та же подпись дважды не выходит, ключ из неё не вывести; два касания (разрешение и Google) —
  цена, названная в спеке.
- **Демон, раздающий access-токен процессам через сокет** — отклонён, потому что сокет отвечал
  бы любой программе того же пользователя, то есть это тот же открытый файл.
- **Refresh-токен в памяти на всю сессию** — отклонён, потому что в памяти жил бы недельный
  токен, а не часовой; владелец принял касание раз в час.
- **Окно на первом же обращении к Google, без строки агента** (буква первоначального
  описания) — заменено объявленным окном через `gc_unlock` при той же частоте касаний, потому
  что иначе правило «окно не ждали — не касайся» нечем выполнять: окно G connect было бы
  неотличимо от чужого.
- **Открытый токен как запасной путь, когда `age` не установлен** — отклонён, потому что это
  тихое понижение защиты; вместо него отказ с командой установки.
- **Отзыв старого входа ПОСЛЕ нового** — отклонён, потому что по документации Google отзыв
  гасит все токены приложения: новый умер бы вместе со старым.
- **Ключ без пароля (`any-biometry`)** — отклонён, потому что владелец выбрал «палец или пароль
  Mac»: с закрытой крышкой доступ остаётся по паролю.

## Риск и порядок

Самое опасное — слайсы 3–4: через хранилище токена пойдёт каждый запрос к Google, и
ошибка закрывает G connect целиком. Поэтому они идут после шва и хранилища, проверенных
отдельно, и с обратными прогонами каждого отказа. Второй риск — окно Touch ID из дочернего
процесса сервера через `age-plugin-se`: у Secretive окно рисует его приложение, здесь —
система по запросу утилиты без окна; проверяется живьём первым шагом слайса 7. Третий —
миграция: отзыв необратим без нового входа, поэтому до него — пробное касание, после —
ожидание подтверждённого отзыва, и `token.json` удаляется только когда новый токен уже
зашифрован и расшифровывается.

## Объём — нужен waiver владельца

Оценка: продукт ~750 строк (шов и хранилище ~300, профили и вход ~150, MCP ~150, CLI
~150), тесты ~650, всего ~1400 строк в ~28 файлах; рисковых путей 4 (`src/core/token/`,
`src/core/auth.ts`, `src/core/profiles.ts`, `src/cli/manual.ts`). Пределы по умолчанию —
25 файлов, 800 строк, 1 рисковый путь. Прошлый живой прогон добавил ~400 строк починок —
запас нужен. Просьба: `max_files_touched=35 max_loc_diff=1800 max_runtime_paths=4`.

## Уроки архива (INDEX: пересечение путей с диффом)

- **L23, L28, L32** — фейк шва согласен сам с собой: тесты шифрования гоняют НАСТОЯЩИЙ `age`
  с программным ключом X25519; фейк — только источник касания. Анклав и окно — живьём.
- **L26, L27, L21** — `gc_unlock` судится через настоящий протокол; незнакомое поле —
  отказ; схема инструмента — из того же источника, что ядро; проба считает восемь.
- **L15** — агентский прогон проверяет механику, не касание человека: касания в живом
  прогоне — только владельца, это названо в чек-листе.
- **L19** — порядок шагов чек-листа и миграции — несущий: пробное касание → отзыв →
  подтверждение отзыва → вход → удаление; проверен тестом на порядок вызовов.
- **L24** — живой прогон пишет только в свой тестовый файл.
- **L29** — тесты шва без `age` не молчат: пропуск называет, что не проверено; в CI `age`
  ставится, пропуска нет.
- **L30** — один механизм — один смысл: окно Touch ID для Google вызывает только
  `gc_unlock`, CLI — только в команде, которую набрал человек.
- **L31** — мутации в verify — теми же долями, что CI.
- **L33** — памятка и подключение меряются настоящим `claude mcp get` и чтением
  `~/.claude/CLAUDE.md`, а не по документации.
- **L5** — пустое и закрытое называет ядро: «Google закрыт» в `gc_targets`, а не ошибка
  первого запроса.
- **L14** — новое поле пишут и читают обе стороны: `token.meta.json` пишет вход и
  перешифровка, читает статус; тест на круг.
- **L2** — поставка в ветке `feat/token-touch`, мерж только через `merge_guard.sh`.
- **L3** — шов с googleapis судится отдельным тестом на ответ по документации: отзыв
  (`invalid_token` — уже отозван) и «жив ли вход» (`invalid_grant` — нет); живые ответы —
  в прогоне `gc seal`.
- **L4** — DESIGN не опережает код: D-24 пишется в том же коммите, что механизм, и каждое
  обещание в нём держит правило с пробой (`token.sealed-at-rest`, `google.unlock-only-tool`).
- **L6** — обещание в ответе исполняет механизм: «Google открыт до HH:MM» в `gc_targets` и
  `gc_unlock` — это срок хранилища процесса, тест U5 судит истечение.
- **L8** — id U1…U14 совпадают по форме с адресами ячеек; проверено grep по `tests/` и
  `src/`: колонку U не использует ни одна фикстура, совпадения — только названия тестов.
