# Plan: два профиля рядом — личный и второй аккаунт Google в одной сессии

Класс M: новое решение (D-25 — сервер на профиль, профиль виден в имени и ответах), смена
раскладки разрешений (механизм безопасности D-23), откат по профилю, подключение по списку.
Слайсы идут от ядра к подключению: сначала сервер знает и называет свой профиль, потом
разрешение и откат перестают его путать, и только потом второй сервер появляется в сессиях.

## Slices

1. **Профиль сервера в ответах** (`src/mcp/server.ts`, `src/mcp/tools.ts`, новый
   `src/mcp/targets-tool.ts`, `src/mcp/unlock-tool.ts`, `src/core/token/vault.ts`). Имя
   сервера — одной функцией (`default` → `g-connect`, иначе `g-connect-<профиль>`). Первая
   строка инструкций — «Сервер G connect профиля „work“ (`g-connect-work`): …». `gc_targets`
   переезжает в свой модуль (`tools.ts` — 499 строк из 500) и отдаёт `profile` (свой: имя,
   сервер, Google, вход, предупреждения) и `otherProfiles` (имя → сервер) вместо списка
   `accounts`. Строка перед окном — функцией профиля, у `default` — прежняя слово в слово;
   её несут `google_locked`, `gc_targets` и `gc_unlock`. Примеры W2, W3, W7, W10.
2. **Разрешение на пару «проект, профиль»** (`src/core/grant/grants.ts`,
   `src/core/write-right.ts`, `src/mcp/grant-tool.ts`). Файл —
   `~/.gconnect/grants/<профиль>/<проект>.json`; прежний `grants/<проект>.json` не
   читается. Фраза — «открой G connect (work)», у `default` — прежняя. Примеры W4, W6.
3. **Откат своего профиля** (`src/core/undo-shared.ts`, `src/core/undo.ts`,
   `src/core/undo-docs.ts`). Запись выбирается по проекту, цели и профилю; если по цели
   есть только записи другого профиля — отказ с именем сервера, которым откатывать. Пример
   W5.
4. **Подключение по списку профилей** (`scripts/connect_claude.sh`,
   `scripts/connect_claude_edit.py`). `--profiles default,work` (по умолчанию `default`):
   на каждый — запись user на стабильную сборку и local на dev-сборку репозитория, правило
   `mcp__<сервер>__*`, строка в памятке; показ без `--apply` — по каждому профилю;
   `--disconnect` с тем же списком; профиль без каталога в `~/.gconnect` — отказ до
   записи. Примеры W1, W8, W9, W10.
5. **Правила и дизайн** (`src/policy/rules.md`, `src/policy/rules.json`, `DESIGN.md` D-25,
   `scripts/probe_mcp.mjs`). Правила `grant.per-profile` и `undo.own-profile` с пробами;
   проба собранного сервера судит первую строку инструкций.
6. **Verify до живого прогона** (L37): мутации долями, как CI (L31); `decisions.md`,
   дайджест ожиданий на подпись, блоки «исполнение рисковых путей», «поверхность модели»,
   «ревью рисковых мест».
7. **Живой прогон** — касания и слова владельца: стабильная из ветки → подключение
   `--profiles default,work` (слово владельца) → новая сессия в соседнем проекте: W1, W2,
   W3 (касание рабочего, личный закрыт), W4 (разрешение рабочего по фразе владельца,
   личное цело), W9. W5, W6, W8 — тестами (W5 живьём требует файла, доступного обоим
   аккаунтам, — пишем только в своё, L24; W8 живьём сняло бы настоящее подключение).

## Rejected alternatives

- **Один сервер на оба профиля с аргументом `account` в каждом вызове** — отклонён, потому
  что хранилище токена, касание, разрешение и журнал живут в процессе одного профиля, а
  агенту пришлось бы выбирать аккаунт в каждом вызове: промах — запись не тем аккаунтом.
  Два сервера делают профиль видимым в имени инструмента.
- **Профили — все каталоги `~/.gconnect` с ключом клиента** — отклонено, потому что
  полуготовый или тестовый профиль стал бы сервером в каждой сессии; список называет
  владелец при подключении.
- **Один файл разрешения на проект со списком профилей внутри** — отклонён, потому что два
  сервера пишут его одновременно, и гонка затёрла бы чужое разрешение; файл на пару — без
  общего писателя.
- **Перенос старых разрешений в новую раскладку** — отклонён, потому что они живут до 23:59:
  цена — одно касание.
- **Профиль сервера абзацем в `rules.md`** — отклонено, потому что клиент показывает агенту
  ~5 тыс. знаков инструкций из 23 тыс. (замер 2026-10-19): до агента наверняка доходят
  первая строка инструкций, `gc_targets` и памятка.
- **Переименовать личный в `g-connect-personal`** — отклонено словом владельца, потому что
  ломает правило `mcp__g-connect__*` и памятку D-24.

## Риск и порядок

Самое опасное — слайс 2: разрешение — механизм безопасности, и ошибка раскладки молча
открыла бы запись не тому профилю или закрыла обоим. Поэтому обратные прогоны: разрешение
рабочего не открывает личный, старый файл не открывает никому. Второй риск — слайс 4 правит
конфиги Claude Code владельца: тесты — на временном каталоге с фейком `claude`, сверенным
с настоящим порядком аргументов (L32), живьём — только словом владельца и с копией. Третий
— первая строка инструкций и форма `gc_targets` меняют поверхность модели у обоих серверов.

## Объём — нужен waiver владельца

Оценка с поправкой L36: продукт ~350 строк (сервер и ответы ~120, разрешения ~60, откат
~70, подключение ~100), тесты ~550, правила и дизайн ~150 — всего ~1050 строк в ~24
файлах; рисковых путей 2 (`scripts/connect_claude.sh`, `src/core/grant/grants.ts`).
Пределы по умолчанию — 25 файлов, 800 строк, 1 рисковый путь. Просьба:
`max_files_touched=30 max_loc_diff=1300 max_runtime_paths=2`.

## Уроки архива (INDEX: пересечение путей с диффом)

- **L1** — заявления STATUS сверены с кодом: два рисковых пути, новой зависимости нет,
  поверхность модели — четыре файла.
- **L2** — ветка `feat/two-profiles`, мерж только через `merge_guard.sh`.
- **L3** — шов судится настоящим: разрешение — настоящим `ssh-keygen` (как D-23),
  подключение — живым `claude mcp get` обоих серверов.
- **L4** — D-25 пишется в том же коммите, что механизм; обещания держат правила с пробами.
- **L5** — «записей своего профиля нет» называет ядро — с причиной и именем сервера.
- **L6** — профиль и имя сервера в ответах берутся из того же значения, что выбирает токен
  (`deps.account`), а не из памяти модели.
- **L7** — оракулы отката и разрешения — с обратным прогоном: без фильтра профиля W5
  краснеет, без раскладки по профилю — W4.
- **L8** — id W1…W10: `W` в `tests/`, `src/`, `scripts/` не встречается (0 совпадений);
  `P1…P22` заняты прошлой поставкой — переименование до кода, подтверждение владельца.
- **L9** — новые файлы ядра попадают в маску мутаций без правки списка; скрипты
  подключения судят тесты на временном каталоге.
- **L10** — новая раскладка разрешений и откат по профилю краснят старые оракулы — их
  переводить, а не обходить.
- **L11** — порядок проверок разрешения: профиль сверяется до подписи и срока — оракулом.
- **L12** — тесты пишут только во временные каталоги (`CLAUDE_HOME`, каталог профилей
  теста); живые `~/.claude` и `~/.gconnect` — только словом владельца.
- **L17** — не применимо: связь «превью — запись» поставка не трогает, профиль — не вторая
  подпись.
- **L18** — не применимо: текст разрешения уже несёт профиль, меняется раскладка файлов, а
  не подпись.
- **L19** — порядок чек-листа несущий: подключение → новая сессия → касание; отключение
  живьём не делаем.
- **L20** — гейт длины на `tools.ts` (499 из 500): `gc_targets` — в свой модуль.
- **L21** — имя сервера — одно правило; ядро и скрипт подключения сверяет один оракул.
- **L22** — на verify — чтение без прогона: связи «профиль назван» ↔ механизм.
- **L23, L28, L32** — фейк `claude` и фейк журнала согласны сами с собой: подключение —
  живьём, откат — на настоящем журнале во временном каталоге.
- **L24** — живой прогон пишет только в свои файлы; W5 живьём не гоняем.
- **L25** — гейт — только с `--diff-base main`.
- **L26** — инструменты и инструкции — через настоящий протокол (`tests/fixtures/protocol.ts`).
- **L27** — опечатка в списке профилей — отказ с названием, а не тишина.
- **L29** — заявление про оракул несёт дату зелёного прогона.
- **L30** — строка перед окном и фраза разрешения — одна функция профиля для ядра, памятки
  и правил.
- **L31** — мутации в verify — долями, как CI.
- **L33** — приоритет областей меряется: `claude mcp get g-connect-work` из репозитория
  (dev) и снаружи (стабильная).
- **L34** — не применимо: запуск процессов не меняется.
- **L35** — шаги с касанием — скриптом сессии, по процессу на профиль; отказ разбирается
  телом верхнего уровня.
- **L36** — оценка с поправкой: тесты ~550 из ~1050.
- **L37** — `decisions.md`, дайджест и блоки verify — на implement, до живого прогона.
