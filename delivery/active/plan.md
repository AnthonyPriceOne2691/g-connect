# Plan: MCP-сервер (фаза 2)

## Approach

Четыре слайса, каждый заканчивается зелёными гейтами.

1. **Граница и правила.** `core/ops.ts` (zod-схема операций), `policy/rules.md` + `rules.json`,
   исполнение правил в core. Тесты: схема отклоняет мусор до вызова Google; каждое правило
   из `rules.json` имеет отказ (B6, B7, и требование «правило = механизм, а не текст»).
2. **Журнал и откат.** `core/audit.ts`, `core/undo.ts`: снимок «до», обратная запись,
   сверка ревизии. Тесты на моках (B9, B10, B11).
3. **Сервер.** `src/mcp/server.ts` на официальном SDK: шесть инструментов, ресурс
   `policy://rules`, `instructions`. Сборка `dist/`. Тесты: `tools/list` даёт шесть штук
   со схемами; ошибки уходят как payload, а не как исключение (B1, B2, B8).
4. **Превью и живая проверка.** `core/report/html.ts` (B12), подключение к Cursor и
   Claude Desktop, ручной прогон одной формулировкой в двух клиентах (B13).

Порядок неслучаен: правила и журнал — до сервера. Иначе сервер появится раньше механизма,
который его ограничивает, и первая же запись пройдёт мимо аудита.

## Stack / boundaries

- `@modelcontextprotocol/sdk` (TS), stdio-транспорт. Никаких HTTP в этой фазе.
- **Ядро не знает про MCP.** `src/core/**` → `src/mcp/**` запрещено; судит `layers-gate`
  (правило `core-is-leaf`), а не договорённость.
- Сборка: `tsc` с `emitDeclarationOnly: false` в `dist/`; `allowImportingTsExtensions`
  придётся снять — риск назван в фазе 1 (§Ревью рисковых мест, п.3).
- Файл ≤ 500 строк (гейт `file-length`), сложность ≤ 10 у нового кода (гейт `complexity`).

## Rejected alternatives

- **Написать протокол MCP руками** — отклонён: транспорт, кадрирование и схемы придётся
  поддерживать самому, а SDK официальный и его контракт меняется вместе со спекой.
- **Отдавать 30 мелких инструментов вместо шести** — отклонён по D-4/§3: контекст клиента
  раздувается, а агент начинает путаться в арифметике индексов; проверено на постановке.
- **Правила только текстом в `instructions`** — отклонён: правило, которое живёт лишь как
  текст для модели, не является правилом (D-12). `rules.json` исполняет core.
- **HTTP-транспорт сразу** — отклонён: клиенты фазы 2 (Cursor, Claude Desktop) работают по
  stdio, а открытый порт — новая поверхность без надобности (§13.2 границы).
- **Аудит после сервера** — отклонён: тогда первые записи пройдут мимо журнала, и «кто
  что записал» восстановить будет нечем.

## Risks

- **`allowImportingTsExtensions` и сборка.** Расширения `.ts` в импортах ломают `tsc` с
  emit. Смягчение: перейти на импорты без расширения либо собрать бандлером; решается в
  слайсе 3, риск назван заранее (урок фазы 1).
- **Схема инструмента ≠ поведение.** JSON-схема во `tools/list` может разойтись с zod-схемой
  внутри. Смягчение: схема генерируется ИЗ zod, а не пишется вторым текстом.
- **Правила в трёх местах** (`rules.md`, `rules.json`, `instructions`). Смягчение: тест
  «каждое ограничение из `rules.json` имеет отказ в core» + `instructions` собирается из
  `rules.md`, а не копируется.
- **Ошибка как исключение вместо payload.** MCP-клиент покажет стектрейс. Смягчение: единый
  перехват на границе сервера, тест на форму ответа при брошенном `GcError`.
- **Живая проверка B13 требует человека** — как и в фазе 1; планируется, а не всплывает.

## Rollout / migration

`npm run gc` (обвязка фазы 1) остаётся рабочей всю фазу — это страховка, если сервер
окажется недоступен клиенту. Старый `Gdocs-tabs editor` не трогаем до фазы 3.

## Test / eval strategy

- Слайсы 1–3: `vitest` на моках, ни одного сетевого вызова. Примеры B1–B12 — по тесту на
  пример, помеченному id (§3.1d).
- Реляционные оракулы (§6.5): «любая операция без `dryRun: false` не пишет», «любая ошибка
  ядра уходит клиенту с `code` и `action`», «undo возвращает лист к прежнему состоянию».
- Слайс 4: B13 руками в двух клиентах; результат — в `verify-report.md` блоком
  «Исполнение рисковых путей» по `src/mcp/server.ts`.
- Мерж — только через `bash scripts/merge_guard.sh feat/phase-2-mcp main` (урок L2).
