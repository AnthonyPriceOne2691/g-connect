# Plan: подпись окна Touch ID (2026-11-27)

1. `src/core/token/finger-window.ts` — новый модуль: `fingerWindow(account)` (папка рядом с ключом,
   имя — `profileLabel`), `prepareFinger(plugin, window)` → папка или причина сбоя, `shimText`,
   `fingerFileName`. Копия — `copyFile` с `COPYFILE_FICLONE` из `realpath` плагина (ссылка Homebrew
   не копируется ссылкой), обе записи — через временное имя и `rename`, права 700. Копия и прокладка
   пишутся при каждой расшифровке: клон APFS мгновенный, свежесть не надо сверять.
2. `src/core/token/age.ts` — `unsealWith(…, { timeoutMs, window })`: с окном папка подписи встаёт
   первой в `PATH` расшифровки; сбой подготовки — `PATH` прежний, а `unlock_declined` дописывает
   причину окна без подписи. Шифрование и `keygen` не меняются.
3. `src/core/token/sealing.ts`, `src/core/token/seal-flow.ts` — расшифровка профилем передаёт
   `fingerWindow(account)`; строка пробного касания `gc seal` называет окно.
4. Правило `google.unlock-window-named` (rules.json, проба), абзац «Про доступ» в `rules.md`,
   строка D-24 и §11.5 в DESIGN; комментарии `profile-names.ts` и `unlock-tool.ts`.
5. Тесты на заглушках `age` и плагина (J2–J8), проводка профилем; живой прогон J1 — палец владельца.

## Rejected alternatives

- **Общая прокладка `~/.local/share/finger/bin` + `FINGER_LABEL`** — отклонён владельцем (ответ «Своя
  папка G connect»), потому что G connect стал бы зависеть от файла вне своего контроля, а граница
  D-24 расширилась бы на чужую папку.
- **Ссылка или `argv[0]` вместо копии** — отклонён, потому что имени окна они не меняют (проверка 27.11).
- **Сверять свежесть копии временем изменения** — отклонён, потому что `copyFile` время не переносит, а
  сверка — лишние ветки; запись при каждой расшифровке проще и заодно стирает чужую правку копии.
- **Отказ открыть Google, если подпись не легла** — отклонён, потому что отказ из-за подписи хуже окна
  без подписи (совет сессии portfolio-site).
