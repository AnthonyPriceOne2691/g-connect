# Plan: длинные листы — запись по всему листу, чтение целиком

Класс M: дефект безопасности записи (затирание строки 501), смена поведения чтения по
умолчанию в шве Google, новый вход `gc_read` (`fromRow`). Первым — фейк, режущий как Google,
и тест-воспроизведение, красный на нынешнем коде; потом запись; потом чтение.

## Rejected alternatives

- **Поднять потолок чтения для всех до 5000** — отклонено, потому что запись на листе в
  6000 строк снова считала бы по части, только позже; безопасно — когда частичное чтение
  нельзя получить, не попросив его явно.
- **Запрет записи на листах длиннее 500 строк вместо починки** — отклонён, потому что
  владелец выбрал «запись первой» с настоящей записью: таблица продаж — 1630 строк.
- **Искать ключ `upsertRow` чтением одной колонки** — отклонено, потому что предусловие,
  превью и откат всё равно читают ячейки строки; один снимок листа — одна правда для всех.
- **Сдвигать строки окна пустыми в начале, чтобы переиспользовать снимок** — отклонено,
  потому что карта на таком снимке искала бы шапку в пустоте; окно — отдельный вызов
  `readRows` со строками от `fromRow`.
- **Только инструменты выравнивания, без наследования вида при дозаписи** — отклонено, потому
  что каждая дозапись снова ложилась бы шрифтом по умолчанию и требовала бы нового выравнивания
  (владелец: касание должно открывать работу, а не переписку).
- **Читать `effectiveFormat`** вместо `userEnteredFormat` — отклонено, потому что ядро судит и
  откатывает явный вид (§6); дописанная строка без явного вида видна как `{}`, и этого хватает,
  чтобы найти разницу.
- **Пустое `where` — все строки** — отклонено, потому что забытое условие перекрасило бы лист;
  все строки — только явным `allRows: true`.
- **Вид дат по локали для любой локали** — отклонено, потому что «день.месяц.год» верен только
  для перечисленных: в `en_US` «10.09.2026» Google прочитал бы как 9 октября.

## Риск и порядок

Самое опасное — слайс 2: смена поведения по умолчанию в шве, через который идут все записи.
Поэтому первым — фейк, режущий как Google (иначе тесты снова согласны сами с собой), и
тест-воспроизведение, красный на нынешнем коде. Второй риск — производительность записи на
длинных листах (целое чтение) — названа ценой. Третий — Q14: новый запрос на пути каждой
дозаписи, и сброс `null` в маске полей Google (Q12): оба видны только живьём, поэтому рисковым
путём объявлен шов Google целиком (`src/core/google/`).

## Объём

Оценка с поправкой L36: продукт ~180 строк, тесты ~300, правила и дизайн ~60 — ~540 строк в
~11 файлах; рисковый путь один (`src/core/google/sheets.ts`). В пределах умолчаний
(25/800/1) — waiver не нужен.

Пересмотр 2026-10-19: с Q8–Q10 вышло 909 строк в 18 файлах (L36 — в который раз: тесты
вдвое больше продукта); с Q11–Q15 — ~1500 строк в ~28 файлах. Waiver владельца — 1600 строк и
30 файлов («Да: 1600 строк, 30 файлов»); рисковый путь — шов `src/core/google/` целиком.
