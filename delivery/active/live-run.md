# Живой прогон: Google Docs, уровень 3

Правила и роли — [delivery/LIVE-RUN.md](../LIVE-RUN.md). Здесь только эта поставка.

## Оговорка, которую надо прочитать до прогона (урок L15)

Разрушающие правки подтверждаются **названием предмета** («удаляю абзац …», «заменяю …»).
Агент, называющий предмет сам, проверяет передачу строки между двумя вызовами, а не
подпись человека. Поэтому:

- прогон **агентом** проверяет механику контура (селекторы, план, ревизия, снимки, откат)
  — и это ценно, потому что живой Docs API мы ещё не видели ни разу;
- прогон **человеком** дополнительно закрывает подпись.

Решение о делегации — слово владельца, не выбор агента. Оговорка написана заранее,
как в уровне 2.

## Блокер доступа на 2026-09-09

`npm run gc -- status` → `needs_reauth`, `hasToken: false`. Живого прогона по этой
поставке **не было ни одного**: вход надо восстановить (`npm run gc -- login`), и это
может сделать только владелец. Пока прогона нет:

- **весь шов `documents.*` не виделся живьём.** Фейк построен по документации, и все
  контракты, отмеченными ниже ⚠, — наше ПРОЧТЕНИЕ, а не наблюдение;
- перед первой правкой живого документа обязателен блок «Сверка арифметики» ниже.

## Перед прогоном

1. `npm run gc -- login` — восстановить доступ; `gc status` обязан дать `connected`.
2. `npm run build` — пересобрать `dist`, поднять сервер СВОИМ процессом
   (`node dist/mcp/server.js`), не переиспользуя соединение сессии-редактора.
3. **Создать тестовый документ** (не рабочий!): «Прогноз на матч» с H1, двумя разделами
   H2 («Составы», «Прогноз»), абзацем со смешанными стилями, таблицей 4×3, абзацем с
   эмодзи, вторым табом «Черновики». Добавить его в реестр как `doc-test` с
   `allow: write` и конвертом `{"ops": ["appendText", "insertText"], "maxChars": 1000}`.
4. `node scripts/probe_mcp.mjs --live` — обязана быть зелёной целиком (она сама возьмёт
   первую doc-цель реестра и ничего не запишет).

## Сверка арифметики — ДО первой правки (самое важное)

Наши правила устройства документа выведены из документации и согласованы с фикстурой
оракулом на числах, но живьём не проверялись. Проверяем чтением, ничего не записывая:

| # | Что делаем | Что сверяем |
|---|---|---|
| A1 | `gc_read mode=map` по тестовому документу | табы, оглавление с № абзацев, таблица 4×3 |
| A2 | `gc_read mode=text` таба «Прогноз», `limit: 30` | № абзацев подряд, тексты, стили; абзацы ячеек помечены `inTable` |
| A3 | Абзац с эмодзи | ⚠ его границы: длина текста в UTF-16 (эмодзи = 2 юнита) |
| A4 | Таблица 4×3 в ответе | ⚠ границы строк и ячеек: вход в таблицу 1 юнит, в строку 1, в ячейку 1, пустой абзац ячейки 1 |

**Если A3 или A4 расходятся с нашей моделью — прогон СТОП, правок таблиц не делать:**
на этих числах стоят точки вставки при откате (`docs/table-math.ts`), и промах уничтожит
содержимое соседних ячеек. Расхождение — находка, чинить фикстуру и арифметику вместе.

## Пары фраз

Каждая пара возвращает документ к исходному виду.

| # | Фраза | Что ждём |
|---|---|---|
| 1 | `допиши в конец раздела Составы: «Судья: Раморенко»` | план: якорь «в конец раздела „Составы“», код плана; записи нет (вставка в конверте, но 1000 юнитов ≫ текста → идёт с первой фразы, если конверт подписан) |
| 2 | `откати` | вставленный абзац исчез, соседние целы |
| 3 | `сделай заголовок Составы обычным текстом` | план «HEADING_2 → NORMAL_TEXT»; после записи — обычный текст |
| 4 | `откати` | снова заголовок H2 |
| 5 | `сделай список из трёх абзацев после заголовка Прогноз` | буллеты у трёх абзацев; `откати` снимает их, текст цел |
| 6 | `замени везде Fluminense на Fluminense FC` | план: **число вхождений по табам**, просит «заменяю Fluminense»; голое «да» не проходит |
| 7 | `да, заменяю Fluminense` | `ok`; в тексте замены; ⚠ вхождения В ЯЧЕЙКАХ таблицы НЕ заменены и названы числом в плане |
| 8 | `откати` | исходные вхождения вернулись; «Fluminense FC», бывший в тексте ДО правки, не превратился в «Fluminense» |
| 9 | `удали абзац, начинающийся с «Устаревший прогноз»` (таб «Черновики») | план показывает текст абзаца целиком и просит «удаляю абзац Устаревший …» |
| 10 | `да, удаляю абзац Устаревший прогноз` | `ok`; абзац исчез |
| 11 | `откати` | абзац вернулся на своё место, ⚠ жирные фрагменты — жирные, заголовки — заголовками |
| 12 | `добавь строку в таблицу составов после строки с Иванов` | пустая строка ниже Иванова; `откати` удаляет её |
| 13 | `удали строку таблицы с Иванов` | план перечисляет значения ячеек, просит название |
| 14 | `да, удаляю строку Иванов` → `откати` | ⚠ строка вернулась НА СВОЁ МЕСТО со значениями (главная проверка арифметики) |
| 15 | `вставь картинку https://…/lineup.png после абзаца …` | картинка вставлена Google по URL; `откати` удаляет её |
| 16 | `вставь картинку /Users/anthony/shot.png` | отказ ДО обращения к Google, с советом про отдельную поставку загрузки |
| 17 | правка по doc-цели табличной операцией (`appendRow`) | отказ: цель — документ, с перечнем doc-операций |

Дополнительно, если не жалко минуты:

- `удали таблицу составов` → `откати` — восстановление всей сетки с содержимым.
- Между планом и записью изменить документ руками в браузере → ждём `doc_changed`
  (серверный отказ) и ни одной правки.

## Что считать находкой

- Селектор совпал с несколькими абзацами, а правка прошла (обязан быть вопрос).
- Откат вернул текст БЕЗ стилей или заголовок обычным текстом.
- Откат строки/колонки таблицы вернул содержимое НЕ в те ячейки — сразу стоп.
- Массовая замена откатилась «обратной заменой»: пострадал «Fluminense FC» из исходного
  текста.
- `doc_changed` не пришёл при чужой правке между планом и записью.
- Локальная картинка ушла в Google (обязан быть отказ до сети).
- Ответ отката сказал «откачено», не назвав, что именно вернул.

## Чего этот прогон не проверит

- **Колонтитулы, сноски, разметку страницы, режим предложений** — вне объёма (D-21).
- **Замену внутри ячеек таблиц** — она не делается по построению; в превью названа числом.
- **Конкурентную правку двумя людьми** — нужен второй человек.
- **Загрузку локальных картинок** — отдельная поставка, её ещё нет.
