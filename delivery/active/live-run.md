# Живой прогон U1–U14 — чек-лист (слайс 7, T11)

Касание, пароль Mac и согласие в браузере — **владельца**: агент, нажимающий сам, проверял
бы механику, а не согласие (урок L15). Пишем только в свой тестовый файл — таблицу,
созданную прогоном в «Моём диске», в конце — в корзину (урок L24).

## Порядок — несущий

Стабильная сборка из `main` читает открытый `token.json`; после `gc seal` его нет, и все
сессии Claude Code на старой сборке теряют Google. Поэтому сначала — стабильная сборка из
ветки, сразу за ней — `gc seal`. Между ними сессии отвечают `token_unsealed` — минуты.

| # | Кто | Шаг | Что должно быть |
|---|---|---|---|
| 0 | агент | `npm run build`; `bash scripts/install_stable.sh <коммит ветки>` | проба собранного сервера зелёная дважды; стабильная — коммит ветки |
| 1 | владелец | в терминале репозитория: `npm run gc -- seal` | строка «Пробное касание…» → окно Touch ID (`age-plugin-se`) → палец или пароль (U6, если отменить) → «Отзываю старый вход…» → браузер, согласие → «Готово: токен зашифрован…» |
| 2 | агент | файлы профиля (без вывода содержимого) | `token.json` нет, есть `token.age`, `token.meta.json`, `se-identity.txt`; строки старого и нового refresh-токена нет ни в одном файле (U1) |
| 3 | агент | старый refresh-токен — у Google | `invalid_grant` (U2): проверяет `gc seal` сам, до входа; живой ответ — в его выводе |
| 4 | агент, по слову владельца | `bash scripts/connect_claude.sh --apply` | памятка в `~/.claude/CLAUDE.md` называет `gc_unlock`; резервная копия в `~/.claude/backups/` |
| 5 | владелец | новая сессия Claude Code в соседнем проекте: «прочитай карту таблицы <ссылка>» | агент получает `google_locked`, пишет строку «G connect попросит палец…» и зовёт `gc_unlock` → окно → касание → карта (U3) |
| 6 | владелец | там же, второй запрос в течение часа | окна нет (U4) |
| 7 | владелец | там же: `gc_targets` | «Google открыт до HH:MM» (U12) |
| 8 | агент | `python3 portfolio-site/docs/sales/agencies/gsheet.py` не запускается — только `ls ~/.gconnect/default/token.json` | файла нет: скрипт, читающий его, упадёт (U7) |

| 10 | агент | U5 — истечение | не ждём час живьём: судит тест `token-vault.test.ts` (часы теста) — названо |

разрешением) судят тесты; живьём U8 потребовал бы второй машины, U11 — ответа Google,
который приходит редко. Названо, не скрыто.

## Результат — 2026-10-18, слово владельца «давай прогон»

Касания и отмены — владельца. Шаги 5–7 и 9 вёл агент по его слову («шаги 5–7 сделай сам, а
я только отменю и прикоснусь где нужно»): перед каждым окном — строка в чате.

**Замерено впервые:** окно Touch ID `age-plugin-se` из процесса сервера без окна — показывается,
отмена и касание доходят до ядра; текст плагина на отмене классифицирован как отмена, а не
«ключ не тот».

**Найдено:** `scripts/gc_call.mjs` — один вызов на процесс, а хранилище токена живёт в процессе
сервера: U3, U4 и U12 через него не прогнать. Шаги 5–7 шли скриптом сессии из черновиков
агента (несколько вызовов в одном процессе); в репозиторий он не вошёл — кандидат: режим
сессии в `gc_call.mjs`.

**Не наблюдалось:** поведение свежего агента соседней сессии — строка до окна. Шаги 5–7 вёл
агент поставки; правило доходит до агентов двумя каналами — инструкции сервера (`rules.md`,
«Про доступ») и памятка.
