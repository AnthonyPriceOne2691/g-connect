# Spec: лист из нескольких таблиц — числа в пустые ячейки блока пишутся сами

Хотфикс 2026-11-16 по вести сессии профиля work: на листе, где таблицы стоят одна под
другой, `setCells` не записал 12 чисел часов в пустые ячейки блока работ. Слово владельца — «нужно
ходфиксом быстро реализовать, почему G Connect отказывается заполнять таблички. Это мое слово,
поэтому да, делай»; через сессию — «Должно все срабатывать автоматически».

Идентификаторы примеров — **Y1…Y6** (`Y` в `tests/`, `src/`, `scripts/` и архиве не встречался —
урок L40).

## Problem

Шапка, заданная `headerRow`, считает своими строки до конца листа. На том листе это смешало блоки:
1. колонку часов держали формулы блока итогов на 50 строк ниже — `write_blocked`
   `formula_column`, хотя ячейки записи пусты и без формул;
2. другой колонке часов ядро вывело список букв вариантов из блока ниже —
   `not_in_enum` без плана и кода, и `force` не помогал;
3. поиск строк по условию прогонял колонку условия той же формульной проверкой, что и запись.

Вестью той же сессии позже: ссылка на папку Диска с `u/2/` в пути (браузер с несколькими аккаунтами)
не разбиралась как цель — `ambiguous_target`, а голый ID той же папки проходил.

По дороге найдено: `force` под конвертом (разрешение проекта, `auto` реестра) писал в ячейку с
формулой с первой фразы, без кода плана, — вопреки `write.force-needs-plan`.

## In scope

- Формулы судятся у ячеек записи: формула в ячейке или строкой выше в той же колонке — отказ, как
  раньше; формулы в других строках — заметка в превью.
- Выведенный список — подсказка: значение вне него пишется по типу колонки, превью называет
  список. Список из проверки данных таблицы — вопрос, как раньше.
- Поиск по условию формульной проверки не проходит: он не пишет.
- Правка, которая задевает формулу или защищённый диапазон, конвертом не авторизуется — только
  кодом плана.

## Out of scope (названо, а не забыто)

- Граница не подтверждается у блока без своей шапки («Итоги» из подписей и формул) и у таблицы без
  заголовка, где только один из двух признаков: оформление как у шапки или подпись над числами.
  Выбор шапки без `headerRow` на таком листе — как раньше (может взять строку данных уверенно).
- `appendRow` при одной пустой строке перед следующей таблицей не вставляет строку сам — отказ с
  подсказкой `insertRows` и повтора.
- Правка вида (`formatCells`) судит формулы колонки целиком, как раньше.
- Значение «=…» в колонку со списком из проверки данных сверку со списком не проходит (формула —
  вычисление); строгую проверку данных держит сам Google.

## Комментарии Google (27.11) — PR #25 поверх PR #24

Весть сессии AutoLink Platform (профиль work) 27.11: документ для заказчика создан через G connect,
заказчик ответил в нём комментариями, а `gc_read` их не видит — map, values и text отдают абзацы, но не
комментарии; других путей к Google у сессии нет. Слово владельца — «срочно в оперативном режиме внедрить
возможность G connect читать комментарии в Google Доке и отвечать на них там, и оставлять свои
самостоятельно подсвечивая что-то… как можно быстрее, привлекая агентов».

Префикс примеров — **Z** (`Z` с цифрами в архиве встречается только адресами ячеек вроде `A1:Z46` —
урок L40; номера Z1–Z19 с ними не пересекаются).

**In scope.** Чтение комментариев документа: автор, время создания и правки, текст, `resolved`,
цитата, ответы ветки; № абзаца по цитате в нумерации `mode=map/text` — только при одном вхождении;
текст — данными с пометкой источника. Подсветка фразы фоном текста. Ответ в ветке, закрытие ветки и
свой комментарий с цитатой — в конверте, с откатом.

**Out of scope (названо).** Привязка своего комментария к тексту в интерфейсе Docs: якорь из API
редакторы Google не рисуют (документация Drive) — видимую связь даёт подсветка фразы. Ячейка
комментария таблицы: якорь таблиц — внутренний вид редактора, комментарии таблицы отдаются без места.
Удаление и правка чужих комментариев: Drive разрешает это только автору. Упоминания и назначение
(«+имя»): поля Drive только для чтения, через API не задаются. Предложения (suggestions) — как раньше,
человек принимает их в интерфейсе.
