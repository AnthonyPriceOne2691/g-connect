# Spec: G connect из любого проекта — разрешение касанием пальца

Архитектура — [DESIGN.md](../../DESIGN.md) §3 (контракт инструментов, граница входа D-22),
§11 (безопасность), D-18 (конверт), D-20 (подтверждение разрушающих названием). Открыта по
слову владельца 2026-10-17: «довести до такого уровня, чтобы я мог дёргать G connect в
разных проектах на этом компьютере… прикладываю палец, что-то подписываю, и дальше любой
сессии, где я это говорю, открываются возможности G connect».

Идентификаторы примеров — **X1…X12** («cross-project»). A, B, E — фикстуры, G, K, P, R, V —
прошлые поставки, T — задачи (§3.1d, урок L8).

## Problem

1. **В других проектах G connect нет.** Сервер подключён только в своём репозитории
   (проектный `.mcp.json`) и в Cursor — по пути в РАБОЧУЮ сборку. В соседних проектах у
   агента нет инструментов `gc_*`: одни сессии идут в Google напрямую токеном из
   `~/.gconnect`, другие отказываются («мне нельзя»). Владелец хочет работать с таблицами и
   документами из любого проекта — это его способ работы, а не обход (слово 2026-10-13).
2. **Даже с инструментами писать почти некуда.** Право записи даёт только реестр целей, а
   реестр в `~/.gconnect` правит владелец руками. Создать файл можно только в папку
   реестра; созданный файл права записи не получает; в ПУСТОЙ лист шапку не вписать — запрос
   ahrefs-cases 2026-10-13 («таблица с шапкой и строкой») G connect выполнить не смог.
3. **Подпись человека должна быть такой, которую агент не подделает.** Фразу в чате агент
   не подделывает, но и проверить её не может никто, кроме сессии, где она сказана. Касание
   пальца подписывает разрешение ключом Secure Enclave (Secretive уже стоит на машине):
   подпись проверяется криптографически, а файл разрешения без неё — ничто.

## Users / stakeholders

- Владелец: одна машина, один аккаунт Google (`default`), много проектов.
- Агенты в любых проектах Claude Code (CLI и VS Code). Cursor и Codex — вне объёма
  (решение владельца 2026-10-17).

## In scope

1. **Стабильная сборка сервера.** Отдельный каталог со сборкой из `main` (не рабочей ветки):
   правка в разработке не меняет поведение соседних сессий, пока не выполнена установка.
   Скрипт установки/обновления собирает, прогоняет пробу собранного сервера и только тогда
   переключает.
2. **Подключение для всех проектов.** Claude Code — запись уровня пользователя
   (`claude mcp add --scope user`); в репозитории G connect проектная запись остаётся и
   указывает на dev-сборку. Разрешение инструментов `mcp__g-connect__*` в `~/.claude/settings.json` и памятка агентам
   в `~/.claude/CLAUDE.md` — согласием владельца на шаге установки.
3. **Разрешение проекта касанием (новое решение D-23).** Инструмент `gc_grant` строит
   документ разрешения (проект из `CLAUDE_PROJECT_DIR`, область «своё», срок до 23:59
   местного времени) и подписывает его ключом Secretive через `ssh-keygen -Y sign` — macOS
   показывает Touch ID. Сервер проверяет подпись ключом, который ОТДАЁТ агент Secretive (не
   ключом из файла: файл агент мог бы подменить), и хранит разрешение в
   `~/.gconnect/grants/`. Разрешение без такой подписи не принимается.
4. **Что открывает разрешение («всё своё на срок», решение владельца).** Чтение — как и
   сейчас, всего. Запись — в любые таблицы и документы аккаунта (права файла проверяет
   Google): неразрушающие правки с первой фразы, как в конверте; разрушающие — по-прежнему
   фразой владельца с кодом плана (D-20). Создание таблиц, документов и папок — в «Моём
   диске», созданное сразу доступно для записи под тем же разрешением.
5. **Таблица со шапкой.** `createSheet` принимает `columns` (шапка) и `rows`; запись текстом
   (`asText`, RAW) — даты остаются строками.
6. **Журнал помечает проект;** откат из проекта видит только записи своего проекта (по id
   — явно и с проверкой проекта).
7. **Видимость и отзыв.** `gc_targets` показывает разрешение проекта и его срок; отзыв —
   `gc grant --revoke` в CLI. Отказ без разрешения — объект ошибки с действием: «попроси
   владельца сказать „открой G connect“ и приложить палец».

## Out of scope (названо, а не забыто)

- Доступ по ссылке («все, у кого есть ссылка») — внешнее действие, отдельная поставка со
  своим охранником.
- Отправка писем через ядро (право `gmail.send` у токена есть, операции нет).
- Хук, запрещающий соседним сессиям ходить в Google напрямую, — владелец не считает это
  проблемой (2026-10-13).
- Второй аккаунт Google, общие диски, комментарии.
- Cursor и Codex: их конфиги не трогаем (решение владельца 2026-10-17); проектная запись
  `.cursor/mcp.json` в репозитории остаётся как есть.
- Публикация приложения из статуса Testing (вход раз в 7 дней) — решение владельца «в конце».

## Acceptance (observable)

Из любого проекта Claude Code агент видит инструменты G connect без запроса разрешений;
запись без касания не проходит; после касания — проходит до конца дня и только в этом
проекте; поддельный файл разрешения не принимается; таблица со шапкой и строкой создаётся
одной фразой и откатывается в корзину.

## Acceptance examples

| id | Пример | Что ждём |
|---|---|---|
| X1 | новая сессия Claude Code в другом проекте: «какие у тебя есть цели G connect?» | `gc_targets` вызывается без запроса прав; в ответе — «записи нет: попроси владельца открыть G connect» |
| X2 | там же, без разрешения: «допиши строку в таблицу <ссылка>» | отказ `needs_grant` с действием для человека; ни одной записи |
| X3 | «открой G connect» → `gc_grant` | всплывает Touch ID; палец — `granted` до 23:59 с названием проекта; отмена или 60 с тишины — `grant_declined`, разрешения нет |
| X4 | в `~/.gconnect/grants/` подложен файл разрешения без подписи или с подписью чужим ключом | не принимается: `needs_grant`, ни одной записи |
| X5 | разрешение выдано проекту A, запись идёт из проекта B | `needs_grant` |
| X6 | время после срока разрешения | `needs_grant`, в ответе — когда истекло |
| X7 | под разрешением: «создай таблицу „Тест G connect“: шапка domain, period_start; строка x.com, 2025-06-01 текстом» | таблица в «Моём диске», шапка и строка, дата — строка; ссылка в ответе; `gc_undo` — в корзину Drive |
| X8 | под разрешением: «обнови статус в таблице <ссылка не из реестра>» (`upsertRow`) | пишет с первой фразы, запись в журнале с проектом |
| X9 | под разрешением: «удали строку X» в той же таблице | план и просьба фразы «удаляю строку X»; без неё — `confirm_required` |
| X10 | `gc_undo` в проекте B по записи проекта A | отказ: запись чужого проекта |
| X11 | правка в рабочей ветке G connect собрана, установка не выполнялась | соседние сессии работают на прежней стабильной сборке |
| X12 | сессия внутри репозитория G connect | работает dev-сборка (проектный `.mcp.json`), снаружи — стабильная |

## Non-functional

- Ожидание касания — не дольше 60 с, затем `grant_declined`; запрос не держит сервер.
- Подпись проверяется при каждом запуске сервера и перед каждой записью по кэшу процесса;
  ключ — тот, что отдаёт агент Secretive, по имени, выбранному на установке.
- Секреты остаются в `~/.gconnect`; разрешение не содержит токенов.
- Ни одна правка в обход превью, журнала и отката не появляется.

## Решения владельца (2026-10-17, вопросы с вариантами)

- Касание открывает «всё своё на срок»: читать всё, создавать в «Моём диске», писать в
  любые свои таблицы и документы — через превью, журнал и откат; разрушающее — его фразой.
- Срок разрешения — до конца дня (23:59 местного).
- Механизм — Secretive / Touch ID (предложение владельца).
- Клиент — только Claude Code: запись уровня пользователя, `mcp__g-connect__*` в
  `~/.claude/settings.json`, памятка в `~/.claude/CLAUDE.md` (с резервной копией).
