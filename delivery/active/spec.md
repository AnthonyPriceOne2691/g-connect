# Spec: Google Docs — полное покрытие правки текста (уровень 3)

Архитектура — [DESIGN.md](../../DESIGN.md) §4 (селекторы вместо индексов), §10 (откат),
D-16/D-17/D-18/D-20 (подпись плана, предусловие, конверт, подтверждение названием).
Открыта по решению владельца 2026-09-04: «Google Docs, полностью покрыть». Это второй
продукт на том же контуре, а не расширение Sheets: свой шов (`documents.batchUpdate`),
своя адресация (текст, а не колонки), своя форма снимка.

Идентификаторы примеров — **P1…P22** («paragraph»). A, B, E заняты фикстурами, V, R, K,
G — предыдущими поставками, T — нотацией задач в tasks.md (§3.1d, урок L8).

## Problem

1. **Агент умеет создать документ, но не умеет в нём ни одной правки.** После уровня 2 в
   ядре 21 операция — и все про таблицы; `createDoc` создаёт файл, писать в который нечем.
   Сценарий владельца — контентные документы (прогнозы, разборы: заголовки, абзацы,
   таблицы составов), правка фразами: «допиши в конец раздела», «замени везде», «убери
   черновой абзац».
2. **Голый Docs API для этого непригоден по построению.** Адрес правки — пара UTF-16
   индексов, которые сдвигаются каждой правкой; «абзац про составы» как понятие
   отсутствует. Официальный MCP Google на Docs отдаёт два инструмента (read + сквозной
   update) — без превью, журнала и отката. Мы делаем обратный обмен, как в уровне 2:
   перечислимый список операций, каждая с построенным откатом.
3. **С D-18 обратимость — главный охранник,** и для Docs её надо строить заново: снимок
   ячеек не описывает «абзац исчез», а обратная операция вставки в тексте — это удаление
   диапазона, границы которого сдвинулись бы любой соседней правкой.
4. **У Docs есть то, чего нет у Sheets, и этим надо пользоваться:** серверный optimistic
   lock. `batchUpdate` принимает `writeControl.requiredRevisionId` и сам отказывает, если
   документ ушёл. Предусловие D-17 здесь не перечитка своих ячеек, а родной механизм API —
   и урок L18 (негодный `version` Drive) не повторяется: `revisionId` документа выдаёт и
   сверяет сам Docs API, серверным отказом, а не нашим сравнением.

## Users / stakeholders

Владелец: правит рабочие документы фразами из MCP-клиента. Дальше — те же клиенты, CLI
фазы 3, раннер фазы 4 через тот же core.

## In scope

Операции сгруппированы по **форме отката** — это же порядок слайсов.

**A. Вставки (откат = удаление вставленного диапазона; охранник: вставленное не правлено —
иначе отказ, как G4 уровня 2).**
`appendText` (в конец сегмента), `insertText` (по селектору места), `insertPageBreak`,
`insertTable` (rows × cols), `insertTableRow`, `insertTableColumn`, `insertInlineImage`
(по URL, доступному Google, — ограничение живёт механизмом: правило в policy, отказ ДО
обращения к Google на локальный путь с советом (P19b); см. решения).

**B. Удаления и замены (откат = вставка снимка: текст И стили посегментно).**
`deleteParagraph`, `deleteRange` (escape hatch — явные индексы), `deleteTable`,
`deleteTableRow`, `deleteTableColumn`, `replaceText` (в пределах селектора),
`replaceAllText` (по сегменту/табу/документу).
**Про `replaceAllText` отдельно:** Google возвращает только ЧИСЛО замен, не позиции.
Поэтому снимок позиций и исходного текста каждого вхождения строится ДО правки нашим
чтением, и откат идёт по снимку, а не «обратной заменой»: обратная замена затронула бы и
те вхождения строки-замены, которые были в тексте до правки (P7).

**C. Стили (откат = возврат прежних полей из снимка).**
`updateTextStyle` (bold, italic, underline, strikethrough, link, fontSize, color — по
селектору), `setParagraphStyle` (namedStyleType: обычный текст / H1–H6, выравнивание),
`createParagraphBullets`, `deleteParagraphBullets`.

**D. Чтение — карта документа (`gc_read`, mode: map | text).**
Карта: табы (заголовок, id), оглавление (заголовки с уровнем и № абзаца), таблицы (номер,
размер, первая строка), счёт абзацев и символов, предупреждения (включённые предложения-
suggestions; сегменты header/footer, которые карта не показывает). `mode: text` — абзацы
диапазона с №, текстом и стилями. № абзаца из карты — валюта селекторов, как имя колонки
в Sheets.

**Механизмы, общие для всех:**

- **Адресация селекторами §4, а не индексами:** `paragraphIndex` (из карты),
  `textStartsWith`, `textContains`, `afterHeading`, `firstParagraph`, `lastParagraph`,
  явная пара `startIndex/endIndex` (escape hatch); для таблиц — номер из карты или якорь
  по содержимому ячейки; `tab` — по заголовку таба. Совпало >1 места —
  `needs_clarification` с кандидатами (№ абзаца + первые слова), НЕ «возьму первое»;
  совпало 0 — ошибка с ближайшими кандидатами (резолвер §8 по духу). Селекторы каждой
  следующей операции вызова резолвятся по документу, каким его оставила предыдущая.
- **Индексы — UTF-16 code units,** как считает Google и как нативно считает JS-строка.
  Эмодзи и прочие суррогатные пары — 2 юнита; вставка «после абзаца с эмодзи» не попадает
  внутрь пары (P17). Фейк шва строится по документированной семантике, с оракулами на
  числах из документации Google — урок L23 в полный рост: семантику шва не предполагаем,
  а берём из доков и сверяем живым прогоном.
- **Предусловие — `writeControl.requiredRevisionId` на каждом `batchUpdate`.** План
  строится на прочитанной ревизии, ревизия входит в код плана (D-16); запись требует её
  же, и если документ ушёл — серверный отказ Google превращается в наш `doc_changed` с
  советом перечитать и перестроить план, ни одной правки (P16). Граница названа:
  `revisionId` валиден ограниченное время (документация Google), протухший план
  перестраивается — это штатный ответ, не дефект.
- **Один вызов = один `batchUpdate`** — Google применяет пакет атомарно, «частично
  применилось» невозможно по построению (лучше Sheets, где неатомарность названа в
  уровне 2). Снимки для отката собираются до записи, из того же чтения, что строило план.
- **Журнал получает текстовую форму записи:** сегмент/таб, диапазон, снимок текста со
  стилями посегментно, для структурных (таблицы) — вид и содержимое. Точная форма — в
  plan.md; обещание спеки: откат возвращает и текст, и стили, и ответ отката называет,
  что вернул (правило `write.undo-names-what-it-cannot` продолжает судить).
- **Бюджет снимка — `write.snapshot-max-chars` = 20 000 UTF-16-юнитов** (подписано). Затронутый диапазон больше бюджета — отказ ДО записи, оба числа
  названы (P18).
- **Конверт и подтверждения (D-18/D-20):** `ENVELOPE_OPS` для документов — `appendText`,
  `insertText`, `replaceText`, `updateTextStyle`, `setParagraphStyle`,
  `createParagraphBullets`, `deleteParagraphBullets`, `insertPageBreak`; мера конверта —
  `maxChars` (вставляемых/затрагиваемых юнитов), не `maxCells`. `NAMED_CONFIRM_OPS` —
  `deleteParagraph`, `deleteRange`, `deleteTable`, `deleteTableRow`, `deleteTableColumn`,
  `replaceAllText`: подтверждение НАЗВАНИЕМ предмета, голое «да» не проходит, конверт их
  не разрешает (P20). Превью «было → станет» показывает затронутые абзацы; у
  `replaceAllText` — число вхождений по табам и вхождения с контекстом.
- **Список операций — единственный источник** (`OPERATION_NAMES` расширяется, транспортная
  схема берётся из ядра): урок L21, оба оракула связи (внутрипроцессный и сквозной через
  собранный сервер в `probe_mcp`) обязаны покрыть doc-операции с первого слайса.

## Out of scope (названо, а не забыто)

- **Комментарии, режим предложений, ревью** (`gc_comment`, хайлайты, `applyDocReview`) —
  отложены решением D-3; документы с включёнными suggestions читаются и правятся в
  текущем состоянии, карта предупреждает об их наличии.
- **Сегменты вне body:** headers, footers, footnotes — правка только тела документа
  (и его табов). Карта их называет, править не умеет и говорит это прямо.
- **Разметка страницы:** `updateDocumentStyle` (поля, размер), `insertSectionBreak`,
  многоколоночность, `pinTableHeaderRows`, merge/unmerge ячеек таблиц.
- **Объекты кроме inline-изображения по URL:** drawings, charts, позиционированные
  изображения; загрузка локального файла картинкой (нужен отдельный upload-шов).
- **Upload локальных файлов** (скриншот → Drive → «доступ по ссылке» → URL для вставки) —
  отдельная поставка сразу следом (решение владельца 2026-09-08, сценарий — комбайн
  SEO-ТЗ со скриншотами): смена прав доступа к файлу — внешнее действие со своим
  охранником, вклеивать его в уровень 3 довеском без правила нельзя.
- **`saveAs` и авто-добавление созданного в реестр** — как в уровне 2, право записи даёт
  только реестр.
- Forms, Slides, Gmail, Calendar.

## Acceptance (observable)

- [ ] Каждая операция проходит контур целиком: план «было → станет», код плана или
      конверт, строка журнала, работающий `gc_undo`.
- [ ] Откат замены/удаления возвращает текст СО СТИЛЯМИ, а не голую строку.
- [ ] Откат вставки удаляет вставленное, только если его не правили; иначе отказ с причиной.
- [ ] Диапазон больше бюджета снимка — отказ ДО записи с обоими числами.
- [ ] Ушедшая ревизия между планом и записью — `doc_changed` серверным отказом, ни одной правки.
- [ ] Разрушающие операции не принимаются конвертом и подтверждаются названием предмета.
- [ ] Неоднозначный селектор — вопрос с кандидатами, а не правка «первого попавшегося».
- [ ] `tsc`, `vitest`, smoke, 23 хука pre-commit зелёные; мутационный счёт не ниже 62%.
- [ ] Живой прогон: вставка, массовая замена, удаление и откат каждого на рабочем документе.

## Non-functional

- **Одно чтение на запись:** снимок и предусловие строятся из того же `documents.get`,
  который строил план; запись — один `batchUpdate`.
- **Журнал не растёт с документом:** снимок только затронутого диапазона, бюджет
  `write.snapshot-max-chars` это гарантирует.
- **Шов один:** все вызовы `documents.*` живут в `src/core/google/docs.ts`, гейт
  `core-no-library` продолжает судить.
- **Карта дешёвая:** один `documents.get` с табами; тела абзацев в карте режутся до
  первых слов.

## Решения по открытым вопросам (подписаны владельцем 2026-09-08)

- **Бюджет снимка — 20 000 UTF-16-юнитов** (`write.snapshot-max-chars`). Правило, а не
  константа: правится без кода.
- **Конверт документов — `maxChars = 1000`** по затрагиваемым юнитам; состав
  `ENVELOPE_OPS` — как в In scope. Покрывает дописывание абзаца, не даёт молча залить
  страницу.
- **Табы — в объёме с первого слайса.** Адресация несущая: доклеивать `tab` потом — значит
  перетрясти якоря и код плана.
- **`insertInlineImage` остаётся, с ограничением «URL, доступный Google», названным
  механизмом** (правило + отказ P19b + передача отказа Google P19). Я предлагал вычеркнуть;
  владелец назвал сценарий — комбайн производства SEO-ТЗ со скриншотами, — и разрез прошёл
  по границе площади риска: вставка по URL здесь, upload локальных скриншотов (со сменой
  прав доступа — внешним действием) — отдельной поставкой сразу следом.
- **`replaceAllText` подтверждается названием ВСЕГДА.** Порог от числа вхождений делал бы
  поведение зависимым от содержимого документа (класс L24): одна фраза сегодня пишет
  молча, завтра просит подпись. Точечная замена без подтверждения есть — `replaceText` по
  селектору в конверте.
