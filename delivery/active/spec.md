# Spec: длинные листы — запись по всему листу, чтение целиком

Архитектура — [DESIGN.md](../../DESIGN.md) §3 (`gc_read`), §9.5 (границы чтения), D-17
(предусловие записи); эта поставка вводит **D-26**. Открыта вестью сессии portfolio-site
2026-10-19 («нужно, чтобы читала всё» — слова владельца) и словами владельца в этой сессии:
«Всё сразу» (чтение) и «Да, запись первой» (объём Q1–Q7).

Идентификаторы примеров — **Q1…Q7** (`Q` в `tests/`, `src/`, `scripts/` и архиве не
встречается — урок L40).

## Problem

1. **Чтение листа обрезано на 500 строках молча.** `getSpreadsheet` с названным листом
   берёт `A1:ZZ500` (правило `read.max-rows`), `gc_read mode=values` считает `truncated`
   по уже обрезанному ответу — признак всегда `false`. Схема обещает `limit` до 5000.
   Лист «Агентства» (1630 строк): видно 499 строк из 1629, строки с 501-й недоступны.
2. **Запись на таком листе затирает чужие данные.** `appendRow` берёт строку «шапка + число
   строк данных + 1» по обрезанному чтению — на листе в 1630 строк это 501-я, занятая.
   Предусловие (`assertBeforeValues`) перечитывает лист тем же обрезанным чтением, видит
   501-ю пустой и пропускает запись. `upsertRow` с ключом ниже 500-й строки ключа не находит
   и уходит в `appendRow`. Превью показывает «было: пусто», откат вернёт пустоту, а не
   прежние данные. Журнал чист — так ещё не писали.
3. **Даже на коротком листе `appendRow` целится внутрь данных при пропуске в середине:**
   число непустых строк — не граница данных (урок L16).
4. **Фейк Google в тестах обрезку не моделирует** — отдаёт лист целиком при любом
   диапазоне; поэтому потолок не видел ни один тест (L23).

## In scope

1. Запись и всё, что её готовит (превью, предусловие, откат, структурные правки), читают
   лист **целиком** — это поведение по умолчанию; частичное чтение — только явным выбором
   в путях чтения. Слишком большой для записи лист — отказ, а не расчёт по части.
2. `appendRow` — после последней строки с данными, а не после числа непустых.
3. `gc_read mode=values`: до 5000 строк за вызов (по умолчанию — предел), `fromRow`, честный
   `truncated` с числом строк листа и строкой продолжения.
4. Карта листа — лёгкая (первые 500 строк), но называет число строк листа и что построена
   по части.
5. Фейк Google режет по диапазону, как Google.

## Out of scope (названо, а не забыто)

- Ревизия таблицы для журнала читает книгу целиком (`server.ts`, `revision`) — дорого на
  больших книгах, но верно; кандидат.
- Чтение без названного листа (`gc_read` по первому листу книги) по-прежнему тянет книгу
  целиком — без потолка, как было.
- Колонки дальше ZZ.

## Acceptance examples

| id | Дано | Делаю | Ожидаю |
|---|---|---|---|
| Q1 | лист на 1630 строк | `gc_read mode=values` без `limit` | все 1629 строк данных одним вызовом, `truncated: false` |
| Q2 | лист на 6000 строк | `gc_read mode=values` | 5000 строк, `truncated: true`, `sheetRows`, `nextFromRow` — с какой строки читать дальше |
| Q3 | лист на 1630 строк | `gc_read mode=values, fromRow: 1001` | строки с 1001-й; `fromRow` в ответе — первая отданная строка |
| Q4 | лист на 1630 строк (или с пропуском в середине) | `appendRow` | запись в 1631-ю (после последней строки с данными); превью показывает её же |
| Q5 | ключ в 1200-й строке | `upsertRow` по ключу | правится 1200-я строка; ни дубля, ни затирания |
| Q6 | лист больше предела записи | любая запись | отказ с числом строк и пределом, ни одной записи |
| Q7 | лист на 1630 строк | `gc_read mode=map` | карта по первым 500 строкам, `sheetRows: 1630` и предупреждение, что построена по части |

## Non-functional

- Безопасность по умолчанию: путь, который забыл сказать, сколько читать, читает лист
  целиком, а не обрезает его.
- Тесты — на фейке, который режет по диапазону как Google; шов — тестом на ответ Google по
  документации (`gridProperties.rowCount`); живьём — на своей таблице в 600 строк.

## Цена — числами

- Запись на длинном листе читает его целиком: 1630 строк × 37 колонок ≈ 60 тыс. ячеек на
  запрос — секунды, а не миллисекунды.
- Ответ `gc_read` на 1630 строк — ~720 тыс. знаков: Claude Code кладёт его в файл
  (замер сессии portfolio-site), контекст не выжигается.

## Решения владельца

- 2026-10-19 · **Чтение — «Всё сразу»**: до 5000 строк, `fromRow`, честный `truncated`.
- 2026-10-19 · **Объём Q1–Q7 — «Да, запись первой»** (вопрос с вариантами; примеры — в
  вопросе): безопасность записи — первым слайсом.
